Stripe Webhook Endpoint

MEOK AI uses Stripe to process payments for MCP tool access (x402 Payment Required flow). This document describes the webhook endpoint, events handled, response format, and security configuration.

Endpoint

MethodPathDescription
POST/api/stripe/webhookStripe webhook event receiver
Production URL: https://api.meok.ai/api/stripe/webhook
Test mode: https://api.meok.ai/api/stripe/webhook?test=true

Events Handled

Event TypeHandlerAction
payment_intent.succeeded handle_payment_success Issue Ed25519 attestation tokens to the buyer. Update attestation balance. Send confirmation to buyer email.
payment_intent.payment_failed handle_payment_failure Log failure reason. Send failure notification to buyer. No attestation issued.
checkout.session.completed handle_checkout_completed Confirm session metadata (tier, project ID). Trigger attestation issuance on payment confirmation.
customer.subscription.updated handle_subscription_update Sync subscription plan changes (e.g. per-batch → per-project). Update attestation pool.
customer.subscription.deleted handle_subscription_deleted Revoke project-tier attestations. Notify customer of access expiry.
invoice.paid handle_invoice_paid Confirm recurring payment. Replenish attestation balance for the period.
invoice.payment_failed handle_invoice_failed Flag account for dunning. Throttle attestation issuance until resolved.

Request Format

Stripe sends POST requests with Content-Type: application/json. The body contains a standard Stripe Event object:

{
  "id": "evt_3P...",
  "object": "event",
  "type": "payment_intent.succeeded",
  "created": 1718612345,
  "data": {
    "object": {
      "id": "pi_3P...",
      "amount": 100,
      "currency": "gbp",
      "status": "succeeded",
      "metadata": {
        "tier": "per_attestation",
        "customer_id": "cus_...",
        "project_id": "proj_..."
      }
    }
  }
}

Response Format

The webhook endpoint responds with a simple confirmation. Stripe expects a 2xx within 30 seconds, otherwise it retries.

Success Response (200)

HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "received",
  "event_id": "evt_3P...",
  "handled_by": "handle_payment_success",
  "attestation_issued": true,
  "token": "ed25519:MEoCAkYwEAYHKoZIzj0CAQYFK4EEAAYDOgAE..."
}

Ignored Event Response (200)

HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "ignored",
  "event_id": "evt_3P...",
  "reason": "unhandled_event_type"
}

Error Response (4xx/5xx)

HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "status": "error",
  "event_id": "evt_3P...",
  "error": "invalid_signature",
  "message": "Webhook signature verification failed. Check your signing secret."
}

Security

⚠ Critical: Always verify the Stripe webhook signature before processing events. Failure to do so exposes your endpoint to forged event attacks.

Signing Secret Verification

Stripe signs each webhook request with a signing secret. The signature is sent in the Stripe-Signature header.

Stripe-Signature: t=1718612345,v1=abc123...,v0=...

Verification steps (backend):

  1. Extract the timestamp (t) and signature (v1) from the Stripe-Signature header.
  2. Concatenate the timestamp, a period (.), and the raw JSON payload.
  3. Compute an HMAC-SHA256 of this string using your webhook signing secret.
  4. Compare the computed HMAC to the v1 signature using a constant-time comparison.
  5. Reject if mismatch, old timestamps >5 minutes, or no Stripe-Signature header.

Environment: The signing secret is stored in environment variables — never hard-coded or exposed in client-side code.

VariableDescription
STRIPE_WEBHOOK_SECRETStripe webhook signing secret (whsec_...)
STRIPE_SECRET_KEYStripe API secret key (sk_live_... / sk_test_...)
STRIPE_PUBLISHABLE_KEYStripe publishable key (pk_live_... / pk_test_...)

IP Allowlisting

Stripe webhook requests originate from Stripe's IP range. Recommended: validate source IP and User-Agent matches Stripe/1.0. See Stripe IP Addresses for the current CIDR list.

Idempotency

Stripe may deliver the same event multiple times. The webhook handler uses the event.id as an idempotency key. Duplicate events return 200 OK with "status": "duplicate" and do not issue additional attestations.

Testing

Use the Stripe CLI to forward events to your local development endpoint:

stripe listen --forward-to localhost:3101/api/stripe/webhook
stripe trigger payment_intent.succeeded

The endpoint also accepts the ?test=true query parameter to enable verbose logging without consuming real attestation balance.
