Keystone Attestation API

Integrate cryptographic compliance attestations directly into your MCP servers, CI/CD pipelines, and monitoring dashboards. Every attestation is a verifiable, tamper-proof keystone certificate.

Authentication

All API requests require a valid MEOK_MASTER_API_KEY in the Authorization header.

⚠️ Keep your API key secure. The keystone signing service uses your key to authorise attestation creation. Rotate keys periodically and never expose them in client-side code. Use environment variables or a secrets manager.

Authorization: Bearer MEOK_MASTER_API_KEY

Your API key can be generated from the dashboard. Each key is scoped to a plan tier — Free keys are rate-limited to 3 attestations/day; Pro and Enterprise have no per-key limit.

Endpoints

Three core endpoints power the compliance attestation lifecycle.

POST Create Attestation

/sign

Sign a compliance attestation for an AI system or MCP server. The payload describes the system under attestation, the target framework, and the compliance claims being made. Returns a keystone certificate with a unique attestation_id.

Request Body

{
  "system_id": "mcp-server-42",
  "framework": "eu-ai-act",
  "claims": {
    "risk_classification": "limited",
    "transparency_art_50": true,
    "conformity_assessment": "self-assessment"
  },
  "metadata": {
    "version": "2.1.0",
    "environment": "production"
  }
}

Response 200 OK

{
  "attestation_id": "att_ks_9f3b2a1c7e8d",
  "status": "signed",
  "keystone_cert": "ks://eu-ai-act/att_ks_9f3b2a1c7e8d",
  "timestamp": "2026-06-23T14:30:00Z",
  "fingerprint": "sha256:a1b2c3d4e5f6...",
  "verify_url": "https://proofof.ai/verify/att_ks_9f3b2a1c7e8d"
}

Parameters

system_idRequired. Unique identifier for the AI system or MCP server being attested.
frameworkRequired. Target compliance framework slug (e.g. eu-ai-act, dora, gdpr). See frameworks for the full list.
claimsRequired. Key-value map of compliance claims. Must conform to the framework's schema.
metadataOptional. Additional context — version, environment, tags, etc.

GET Verify Attestation

/verify/{attestation_id}

Retrieve and verify a keystone attestation by its ID. Returns the full certificate including the cryptographic signature, claims, and verification status. Free and unlimited for all tiers.

Response 200 OK

{
  "attestation_id": "att_ks_9f3b2a1c7e8d",
  "status": "verified",
  "system_id": "mcp-server-42",
  "framework": "eu-ai-act",
  "claims": { ... },
  "signature": "MEOK_KS_v1_a1b2c3d4...",
  "signed_at": "2026-06-23T14:30:00Z",
  "verified_at": "2026-06-23T15:00:00Z",
  "valid": true
}

Error Response 404 Not Found

{
  "error": "attestation_not_found",
  "message": "No attestation found with ID: att_ks_invalid"
}

POST Stripe Webhook

/webhook/stripe

Handles billing events from Stripe. Used internally to manage subscription lifecycle, usage metering, and invoicing for Pro and Enterprise tiers. Accepts Stripe's standard event format with stripe-signature verification.

Request (Stripe Event)

{
  "id": "evt_3P2q4R5S6T7U8V",
  "type": "invoice.payment_succeeded",
  "data": {
    "object": {
      "customer": "cus_AbCdEfGhIjKl",
      "subscription": "sub_1234567890",
      "amount_paid": 19900,
      "currency": "gbp"
    }
  }
}

Response

{
  "received": true,
  "event_type": "invoice.payment_succeeded",
  "processed": true
}

🔐 Webhook signature verification. Always verify the stripe-signature header before processing the payload. Use the stripe package's constructEvent() method with your webhook secret.

Rate limits

Rate limits are applied per API key and reset daily at midnight UTC.

TierAttestations / DayVerify RequestsBurst Rate

🔄 Rate limit headers are returned on every response: X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset. Exceeding the limit returns 429 Too Many Requests with a Retry-After header.

Content-Type: application/json
