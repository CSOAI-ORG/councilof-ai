MCPBench

conformance · seat of the instrument: Seattle · Model Context Protocol deterministic conformance profile

A deterministic conformance profile for the Model Context Protocol — the open client/server protocol layered on JSON-RPC 2.0. The question this lane would answer is narrow and decidable: given a captured MCP exchange, does it follow the protocol's rules, and if not, which rule does it break? That verdict is machine-decidable, so the ground truth is computed by a validator, not judged by a panel or by another model. Nothing has been measured yet. This page publishes that emptiness plainly rather than dressing it as a result.

Statutory / standards anchor

Candidate anchor: Model Context Protocol specification — the conformance-relevant provisions (the initialize handshake and capability negotiation, JSON-RPC 2.0 message framing and request/response id correlation, and the schema of tool and resource results) to be sourced against a single frozen spec revision.

Why this is a candidate and not a citation. MCP is a versioned specification; its revisions are dated and its normative wording changes between them. Pinning a clause without naming the exact revision it came from would be inventing precision this lane does not yet have. The transport base — JSON-RPC 2.0 — is stable and can be cited directly; the MCP-specific provisions are marked to-be-sourced until the corpus is frozen against one named revision, and every item then carries the revision it was written against.

The deterministic scorer

This is the rule that would score the field the moment a corpus exists. It is a real skeleton, not pseudocode: fixed label set, one regex extraction, macro-F1 over the conformance classes, and the three-outcome discipline — an item is MEASURED, an answer that cannot be read is UNPARSEABLE and excluded, and a run whose instrument error exceeds threshold is UNMEASURED. A lane error is never folded into a zero.

#!/usr/bin/env python3
# mcpbench_score.py — deterministic conformance scorer for the Model Context Protocol lane.
# Input: JSONL, one item per line:
#   {"id": "h07", "transcript": [ ...JSON-RPC 2.0 messages... ], "gold": "HANDSHAKE_VIOLATION"}
# The gold verdict is produced by a validator, not a human panel — that is what makes this lane
# deterministic. A model is scored on how well its own verdict matches that machine-decidable label.
import json, re, sys

# The conformance classes. CONFORMANT plus the four rule-families a transcript can break.
LABELS = ["CONFORMANT", "HANDSHAKE_VIOLATION", "FRAMING_VIOLATION",
          "CAPABILITY_VIOLATION", "SCHEMA_VIOLATION"]

# Longest-first alternation so CAPABILITY_ cannot be swallowed by a prefix of another token.
TOKEN = re.compile(
    r"\b(HANDSHAKE_VIOLATION|CAPABILITY_VIOLATION|FRAMING_VIOLATION"
    r"|SCHEMA_VIOLATION|CONFORMANT)\b", re.I)

# Runs whose instrument error rate (dropped transports, timeouts) exceeds this are not scored.
INSTRUMENT_ERROR_THRESHOLD = 0.20
USABLE_N = 30


def extract(text):
    """Read one label out of a model's answer, or None if none is present."""
    if not text:
        return None
    m = TOKEN.search(text)
    if not m:
        return None
    c = m.group(1).upper()
    return c if c in LABELS else None


def macro_f1(pairs):
    """Macro-F1 over LABELS. Unreadable predictions are already excluded before this."""
    tp = {l: 0 for l in LABELS}
    fp = {l: 0 for l in LABELS}
    fn = {l: 0 for l in LABELS}
    for gold, pred in pairs:
        if pred == gold:
            tp[gold] += 1
        else:
            fn[gold] += 1
            if pred in fp:
                fp[pred] += 1
    total = 0.0
    for l in LABELS:
        p = tp[l] / (tp[l] + fp[l]) if (tp[l] + fp[l]) else 0.0
        r = tp[l] / (tp[l] + fn[l]) if (tp[l] + fn[l]) else 0.0
        total += (2 * p * r / (p + r)) if (p + r) else 0.0
    return total / len(LABELS)


def score(items, answers):
    """Return one of three outcomes — MEASURED, UNPARSEABLE-heavy still MEASURED with the
    unreadable count shown, or UNMEASURED — never a wrong-answer zero for a lane failure."""
    errored = sum(1 for a in answers if a.get("instrument_error"))
    if answers and errored / len(answers) > INSTRUMENT_ERROR_THRESHOLD:
        # The instrument failed, so there is nothing to say about the model.
        return {"status": "UNMEASURED",
                "reason": f"instrument error {errored}/{len(answers)} exceeds threshold"}

    gold = {it["id"]: it["gold"] for it in items}
    pairs, unparseable = [], 0
    for a in answers:
        if a.get("instrument_error"):
            continue                       # a dropped transport is not a wrong answer
        pred = extract(a.get("text"))
        if pred is None:
            unparseable += 1                # UNPARSEABLE: excluded, never scored as wrong
            continue
        pairs.append((gold[a["id"]], pred))

    n = len(pairs)
    out = {"status": "MEASURED", "n": n, "unparseable": unparseable,
           "macro_f1": round(macro_f1(pairs), 4) if n else None}
    # No interval below usable_n = 30 — including for us.
    out["quotable"] = n >= USABLE_N
    return out


if __name__ == "__main__":
    items   = [json.loads(l) for l in open(sys.argv[1]) if l.strip()]
    answers = [json.loads(l) for l in open(sys.argv[2]) if l.strip()]
    print(json.dumps(score(items, answers), indent=2))
Deterministic means the gold is computed, not opinioned. Each conformance class maps to a checkable assertion about the transcript — was initialize completed before any other method (HANDSHAKE), does every response carry "jsonrpc":"2.0" and correlate its id to a request (FRAMING), was a method used only after its capability was negotiated (CAPABILITY), does a tool or resource result match its declared schema (SCHEMA). A model is then scored against that machine-decided label. No model judges another model.

Provenance and discipline

Chain of custody, once a run exists: frozen corpus revision → transcript hash → scorer version → per-item verdict → aggregate, each step signed so the observation can be reproduced. The signed artefact is the route and the observation — the transcript that was seen and the label the scorer read from it. It is never a verdict about the third party whose protocol implementation produced the transcript.

Measurement, not certification. A conformance verdict here is a statement about one captured exchange under one frozen spec revision — that this transcript did or did not follow a named rule. It is not a statement that a server, a client, or a model is conformant in general, and it is not a statement of conformity with any standard. It is an observation, signed so it can be checked, and it stops there.
