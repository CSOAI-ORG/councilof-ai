## Comparison with existing efforts — *"What is new, more thorough or otherwise different?"*

**1547 / 4000 characters.**

```
Existing efforts and what is different here.

Sigstore/Rekor gives keyless signing and a transparency log for software artefacts. It does not anchor to an independent timechain and is operated by one consortium. We use Rekor as one of several logs, not as the root of trust.

OpenTimestamps gives Bitcoin-anchored timestamps but proves only that bytes existed; it says nothing about what the bytes assert or whether the assertion can be recomputed.

C2PA covers media provenance, not measurement results.

COMPL-AI (ETH/INSAIT/LatticeFlow) is the closest peer for EU-AI-Act mapping and is the honest comparison to make. It is a static published mapping. It does not sign its outputs, does not anchor them, and does not ship a recomputation harness.

Commercial AI-evaluation companies (Vals AI, LMArena, Patronus) publish leaderboards. None publishes a signed, independently recomputable evidence chain, and all are paid-access at some tier.

What is new: the combination of (a) a signed measurement card whose leaf definition binds subject and source URL, (b) a Merkle root anchored to an independent timechain, (c) a verifier with no dependency on the issuer, and (d) a public corrections ledger - 47 corrections issued to date (`/api/corrections`, 06 Sep 2026) - so that being wrong is recorded rather than quietly edited. We could find no other body publishing all four.
```

## Technical challenges expected during the project

**1534 / 4000 characters.**

```
1. Stamped is not anchored. A fresh OTS stamp carries a PendingAttestation and becomes a proof only when a calendar commits it to a Bitcoin block, hours later, and the proof is upgraded. The two states must be published distinctly and never conflated. We already enforce this in a build gate that fails on copy of the form "N atoms OTS-anchored" while the rail is planned; the challenge is carrying that discipline into the proof format itself.

2. Merkle tree shape. Our published root discloses a tree_caveat: odd-node duplication makes the shape collidable in the CVE-2012-2459 sense. WP2 must either move to a construction without that property or bind the leaf count into the signed preimage. This is a real cryptographic decision, not a documentation task.

3. Single signing key. Every signature in our estate is one Ed25519 key under one did:web. A verifier that checks only that key proves custody, not independence. The threat model must say so plainly, and key rotation must not orphan historical proofs.

4. Recomputation determinism. Re-running a measurement over a remote model endpoint is not deterministic. WP4 must separate what is reproducible (the card's canonical form, the chain, the arithmetic) from what is only re-observable (a live model's output), and report those differently. Overclaiming here would be worse than shipping nothing.

5. Verification without the issuer. The verifier must work when councilof.ai is offline, which means the did:web document, the root and the proofs all have to be mirrorable.
```
