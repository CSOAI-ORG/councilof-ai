# Offline SHA3-512 Merkle profile comparison

This example lets a developer reproduce a narrow result from the open-source
[BIS SDMX Blockchain Validator](https://github.com/bis-med-it/sdmx-blockchain/tree/553c7408593351d05733c7de5ba6b8ae5852d128):
for six synthetic fingerprints, its per-level final-node duplication and an
independent upfront final-leaf padding implementation produce different roots.
The one-, three- and eight-leaf fixtures agree. The construction also binds the
leaf count, so duplicating a final leaf or changing the count in an inclusion
proof cannot preserve the expected wrapped root.

The primary research reference is
[BIS Working Paper 1374](https://www.bis.org/publications/working-paper-1374-verifiable-official-statistics-blockchain-based-approach_1.pdf).
The independent profile is one explicit interpretation of upfront padding; this
example does not decide the normative paper interpretation. The pinned source
implements per-level duplication even though its root-function comment describes
upfront final-leaf padding. That is a reproducible source/comment distinction.

## Run

Python 3.10 or newer, standard library only. From the repository root:

```sh
python3 docs/research/bis-wp1374-merkle/compare_profiles.py
python3 -m unittest discover -s docs/research/bis-wp1374-merkle -p 'test_*.py' -v
```

The first command writes a comparison to standard output. A mismatched fixed
expectation exits with status 1. It works from another directory when invoked
with the absolute script path. It does not download data or require the upstream
application, its framework dependencies, a wallet or a ledger connection.
The Vitest bridge under `scripts/` runs the same Python regression suite in
the existing mandatory scripts test step. Its path also activates that PR gate;
no new workflow or test-file registry is required.

## What is included

- `bis_reference.py`: seven pure hash/Merkle functions extracted with unchanged
  bodies from `app/utils.py` at commit
  `553c7408593351d05733c7de5ba6b8ae5852d128`.
- `compare_profiles.py`: independent upfront-padding implementation and a
  separate strict 64-byte hexadecimal input policy.
- `vectors.json`: a projection of synthetic offline observations recorded on
  8 October 2026. Original method/result hashes and the full upstream source-file
  SHA-256 are retained. Expected roots are fixed evidence, not regenerated by tests.
- `test_compare_profiles.py`: profile, count, proof mutation, input contract,
  provenance, output-claim and portable-command regressions.
- `LICENSE` and `NOTICE`: preserved Apache-2.0 license and BIS attribution, with
  an added notice explaining this extraction and the separate example additions.

The pinned reference accepts hexadecimal fingerprints of 0, 63 and 65 decoded
bytes. Its behavior is preserved here as an input-contract observation. The
comparison helper deliberately requires exactly 64 bytes; this policy does not
alter the reference or establish a vulnerability in a deployed system.

## Boundaries

These are synthetic hash and proof checks. XML canonicalization, schema validity,
signatures, issuer identity, ledger inclusion and deployed interoperability were
not tested. A Merkle match would not establish issuer authority or measurement
quality. The report keeps all those checks false and rejects a fixture that
tries to promote an unexecuted check.

The upstream repository describes an unmaintained research prototype for XRPL
DevNet. This contribution is an independently reusable example in the Council
repository. It is not an upstream patch, a BIS partnership or endorsement,
production compatibility, a signed receipt or a Bitcoin anchor.
