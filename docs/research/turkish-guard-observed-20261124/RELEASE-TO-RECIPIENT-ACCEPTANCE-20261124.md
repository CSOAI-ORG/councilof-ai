## Exactly what was measured, not marketing projection

- Turkish publisher-labelled benchmark (3,372): TP 255, FN 62, TN 2,768, FP 287. **80.44%** attack recall, **9.39%** false-alarm rate; benign task instructions **239/1,000 flagged**. Inference on a pre-existing small open-weight ONNX guard. This does NOT test GPT-6 or any frontier model.
- NotInject (339 publisher-labelled benign): **13 false flags (3.83%)** over three source splits; no attack population, no attack recall. Run was observed on M4. The original local aggregate SHA is retained in a derivative summary and must not be passed off as a published exact original-file readback.
- Older 116-case English test already published on 21 Nov is a reproducibility control only, **not a new discovery**.
- News incident analyses point to falsifiable safety controls; *none* of these incidents was prevented, simulated or replayed on actual affected systems by CSOAI.

## Full end-user and buyer journey that must pass before 'operational'

1. **Discover:** user opens existing CSOAI Agent Authority & Evidence pilot or evidence bundle; landing page states measured numbers, original evidence links, publication date and limits. No new SKU invented.
2. **Inspect for free:** user verifies manifest, model revision, source/parquet hash, method SHA, case metadata SHA, confusion matrix and rights; no login or payment required for public verification. Broken files or altered digests cause explicit uncheckable state.
3. **Try in CouncilOS:** user opens existing Evidence & Learning tab, selects Reaction research, pastes the non-sensitive `councilos-import.json` **array**, reviews OBSERVED model classification and sees missing human, executor, effect and receiver stages. All steps local-only; no self-report 'Verified' label.
4. **Request scope:** user sees existing product/measurement scope and prepares an email via contact flow. An email draft is not a sent enquiry. Backend lead KV storage alone is not successful human delivery. Receiver must be identified and explicitly accept test conditions.
5. **Approve:** company authority verifies/enrols a specific real person, exact action, principal, controlled destination, expiry, revocation and safe rollback. Human authority cannot be manufactured by an AI or inferred from this report.
6. **Execute once:** MEOK runner performs a harmless permitted action only after current authorization; wrong actor/target/replay/revoked requests are rejected with retained receipts; no production, billing, credentials or external attack targets.
7. **Verify effect:** independent receiver, not the actor measured, observes the exact resource bytes and signs a bounded acceptance/denial receipt. The original evidence item, raw method and result are retained with appropriate privacy and data minimization.
8. **Deliver:** buyer receives a source-pinned evidence pack, reproduces checks, and explicitly accepts or disputes quality. Capture revision, price only if separately agreed, delivery time, support and non-paid/real payment distinction.
9. **Correct:** disputed false flags and misses generate a source-linked correction request and a **new blind**, rights-cleared challenge bank; no retraining/test contamination. Corrected copy must show prior and new version and external reviewer.
10. **Reassess and scale:** track accepted external jobs, independent repeat verifications, corrected evidence, false-block cost and true effect prevention; only these denominators underpin market claims, not downloads, HTTP 200 or synthetic tests.

## Product thesis, limited to defensible evidence

**Potential USP:** a portable evidence layer that does more than flag risk: it reports misses and unnecessary refusals, binds sources and methods, separates humans from model decisions, and establishes what an independent recipient *actually observed*. Today we can demonstrate real classifier measurement and honest evidence-gap reporting, but not a fully functioning external authorized-effect chain. Existing free verifier remains free. Sell a bounded evidence bundle or buyer-approved Agent Authority & Evidence pilot under written terms only after true external delivery.

**Commercial metrics:** actual accepted paid external jobs / explicit buying attempts / independently reproduced results / repeat qualified receiving parties / remediation time / variance between method and deployed bytes; do not convert wallet count, downloads, GitHub tests, bot actions or self-enquiries into customer demand.

Only declare the full product end-to-end complete when there is one documented: **authenticated human approval → currently qualified MEOK executor → actual permitted harmless effect → independent recipient observation and acceptance → source-pinned external report → deployed and verified user-facing retrieval**. The actual study in this branch verifies only the earlier source/model/read-only reporting steps. This is a blocker to close, not a pass by fiat.
