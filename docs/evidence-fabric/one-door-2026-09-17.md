# One door, from a buyer's eye

**17 September 2026 · no money spent, no door added, no code changed.**

## The door

**`/api/free-door`.** It is the right one and not by elimination: it is the **only** CSOAI resource
the x402 Bazaar has indexed, because the Bazaar catalogues a resource off a *confirmed settle* and
this is the only door that has ever settled. Every paid door is absent from the index. Perfecting
any other door perfects something no buyer can find.

## What a stranger actually gets

All eleven advertised doors were called **exactly as published**, with no credential and nothing
signed:

| verdict | doors |
|---|---|
| `SELLABLE` — 402 with a well-formed challenge, real `payTo`, real asset, non-zero amount | **10** |
| `SELLABLE_AT_ZERO_declared_free` — 402, well-formed, amount 0, and the discovery document says it is free | **1** (`free-door`) |
| lost sales (400/404 from an advertised URL) | **0** |

**Zero lost sales.** The two document defects recorded on 2026-09-05 — `/api/art50/marking-evidence`
advertising `?vendor=` while the handler read only `url=`, and `/api/evidence-bundle` advertising an
`obligation=<id>` that meant a model id — are both **fixed**: the discovery document now advertises
`?url=` and `obligation=article-50`, and both answer 402 when called that way.

### Zero is not automatically a defect

The rule "no paid door may advertise `amount: 0`" exists because zero trips `verifyX402Payment`'s
*"no amount configured for this resource"* guard, after which the door can never fulfil however
correctly a buyer pays. `free-door` advertises zero **and passes `allowZeroAmount: true`**, so it
fulfils. Its price of zero is the true price.

A genuinely free route answering **200** would be worse, not better: an indexer catalogues a
*payable* resource, so a 200 is not a door at all and cannot be catalogued. That is documented in
the handler as the reason this file exists at all — an earlier seed named `/api/gspc`, which answers
200, and indexed nothing.

The first run of this probe reported all eleven doors as broken. That was **my reader**, not the
doors: it capped the response at 4 KiB and truncated every challenge mid-string, and it looked for
`accepts` at the top level when x402 v2 nests it under `resource.accepts`. Both are fixed and the
cap is gone. Recorded because a probe that is wrong in the pessimistic direction will be believed.

## Exactly where a buyer stops

| step | state | evidence |
|---|---|---|
| 1. discover | **PASSES** | `/.well-known/x402.json` lists 11 resources with `accepts[]` |
| 2. call with no credential | **PASSES** | 402 on all 11, well-formed v2 challenge |
| 3. read the terms | **PASSES** | `payTo`, `asset`, `network: base`, `maxAmountRequired` all present |
| 4. settle | **NOT PROVEN HERE** | needs a funded buyer. This probe signs nothing and spends nothing. |
| 5. retry with `X-PAYMENT` and receive the goods | **NOT PROVEN HERE** | follows step 4 |
| 6. be findable in the Bazaar | **PARTIAL, AND PERMANENTLY DEGRADED** | indexed once on 2026-09-05; the record is written once and never refreshed, and its description is cut mid-clause at 120 chars — *"...free forever — this"*. A later successful settle carrying corrected metadata did not move `lastUpdated`. |

**The door is correct up to the point where money is required, and it stops there because this lane
must not spend.** That is the honest boundary, and naming it is the deliverable.

## The one thing that cannot be repaired

The Bazaar record is permanent. Re-seeding does not fix the truncated description — probed across a
further successful settle, `lastUpdated` never moved. So the estate's only indexed listing will read
`"...free forever — this"` for as long as that index exists. The handler now writes its first
sentence to survive being cut at 120 characters, which protects the *next* listing and cannot
retrieve this one.

## What this does NOT show

- Not that any door earns. The rail has received **0.00 USDC**. A 402 is a challenge, not revenue.
- Not that settlement works today — untested here by design.
- Not that delivery matches the advertised `outputSchema`; that needs a completed payment.
- Not that the paid doors are discoverable. They are **not** in the Bazaar, and only a confirmed
  settle would put them there.
