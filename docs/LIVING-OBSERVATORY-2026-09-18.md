# GSPC Living Observatory — integration delta, 18 September 2026

## Implemented scope
One additive component on the existing GSPC board, not a new website or competing score authority. Seven versioned topic lenses, search, disclosure registers, source dates, partial errors, pagination, CARE/Charter/Layer 0 navigation, and unmeasured reciprocal cups. The underlying board table follows the topic/search filters. CSV remains explicitly the whole board.

Two existing registers are projected without changing their original data: GPAI public-list notices and humanoid deployment disclosures. Their rows are not unique audited companies. No model score is applied to an organisation. No company league table is fabricated. Topic lenses are CSOAI editorial selections, not official control crosswalks, applicability decisions or certifications.

The trust projection admits reviewed, task/context/system-revision-scoped evidence. It preserves contradictions and revocations, rejects expired/future/unreviewed/wrong-scope records and deduplicates repeated evidence. This is a tested prototype projection, not identity verification, a validated psychological measure, a human social score or an enforcement gate. No live contextual trust receipt feed is connected to the two cups yet.

The public-source observer uses only the existing compute, seven exact reviewed public URLs and standard-library HTTP. Each run has seven requests, a one-megabyte per-body bound, no redirects/proxies/credentials, immutable body-addressed blobs, immutable run receipts, last-success lineage, an atomic latest pointer and a single-writer lock. STOP and a source digest prevent unintended unattended execution. At the retention bound it stops rather than deleting evidence. Source byte changes trigger review; semantic/legal conclusions, signatures and measurements remain zero until a separate reviewed process establishes them.

## One engine, distinct responsibilities
Constitution and CARE floors → versioned requirements and applicability → organisation/system/model/deployment/source identities → immutable public/consented observations → versioned held-out evaluations → independently reviewed evidence → contextual, revocable trust → constrained request routing → existing signer, Layer 0/root and witness gates → published evidence and change notifications.

ASI/RSI/neural selection may propose new experiments, choose work within budgets or propose patches. It must not change its own gold labels, remove human-consent controls, count its own opinion as independent review, promote itself, overwrite old evidence, bypass spend limits or reuse obsolete scores after a model revision. The existing worker and scheduler remain authoritative for GPU measurement. This observer performs no inference or robot actuation.

RaaS is receipts/evidence-as-a-service: commissioned or subscribed evidence with visible method, scope, age and correction history. It is not pay-for-favourable-findings or legal certification. Discovery is not authorisation; authority to read public sources is not authority to sign, spend, access private companies' systems or use a third-party identity.

## Coverage contract, not invented coverage
The user's requested universes (23 axes, 16 XRPL instruments, 17 SWIFT banks, 425 stablecoins, enterprises/SMEs/public watchdog, x402/MCP/API/Layer 0) are separate registries with separate denominators. The observer can report actual rows returned by a known collection, not claim that every constituent has been measured. The initial reviewed source allowlist includes the board, XRPL, SWIFT, GPAI notices, humanoid disclosures, the NIST resource centre and the European Commission GPAI page. Stablecoin-wide source monitoring, all company papers, x402/MCP/API conformance and enterprise internal-control inspection are not newly activated by this patch.

## UX design criteria
1. Hick: a bounded set of named lenses, not hundreds of unexplained choices.
2. Fitts: minimum 44px primary controls and generous linked cards.
3. Jakob: native search/select, ordinary links and familiar pagination.
4. Miller: grouped controls, source records and trust detail.
5. Proximity: the qualification, date and source stay beside the claim.
6. Common region: model instruments, organisational disclosures and trust do not merge.
7. Progressive disclosure: advanced source/trust panels are expandable.
8. Recognition over recall: visible labels, record types and retained notice links.
9. Feedback and recovery: loading, unavailable, partial, empty and retry states.
10. Consistency: one published board authority, shared projection logic and unchanged evidence semantics.
These are implementation criteria, not a claim of a completed accessibility or usability audit. Browser interaction, keyboard/screen-reader and mobile acceptance still require direct execution before publication.

## Deployment and rollback
Use the canonical monorepo and established GHA release process. No direct production deploy, signing or wallet action is included. Backups and installation receipts are retained privately under the existing operations entrypoint. New files are installed only when absent or byte-identical. Shared file edits use exact unique seams and a concurrent-change check. Roll back only this recorded patch, not other workers' changes.

Private runtime: python3 living-observatory/living_observatory.py status --state living-observatory/state
Single observation: same command with once; scheduler uses due with a six-hour cadence.
STOP: create living-observatory/state/STOP on the pod. The STOP is specific to this observer; it does not stop the main GSPC worker.
