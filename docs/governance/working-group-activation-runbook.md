# Activate the first human working-group review

This is an operating checklist for the forming Council of AI / Public Watchdog groups. Software availability does not establish a staffed council, membership, independent review, regulatory endorsement or execution authority.

## The first useful cycle

Use COAI-WG-002 (delegation revocation and halt latency) as the initial public or synthetic case. Keep its exact version and source commit in the review. Complete one review before expanding to all seven groups. The register maps the 33 declared axes; unmeasured axes remain unmeasured.

| Step | Responsible role, to be accepted | Concrete result | Completion evidence |
| --- | --- | --- | --- |
| Accept operating duties | Coordinator and backup moderator | Consenting people accept scoped duties, availability and escalation route | Permission and conflict records; publish only agreed fields |
| Invite a small review cohort | Coordinator | Subject expert, independent reproducer and affected-user/accessibility participant receive a specific invitation | Actual sent message and response; an unsent draft is not recruitment |
| Confirm the brief | Accepted editor | Public/synthetic case, method, source revision, review window and support needs | Pinned proposal and agreed scope; no assumed budget or employer endorsement |
| Reproduce and challenge | Consenting reviewers | Separate observations, failures, unknowns, conflicts and dissent | Reproduction record; rerunning the same code alone is not independent validation |
| Record a reasoned decision | Existing authorised human review process | Accept, revise, defer or withdraw with rationale and dissent | Actual human review reference and the identity/authority evidence required by that service |
| Publish and offer appeal | Editor and moderator | Permission-checked outcome, version history, appeal route and next review date | Canonical repository record and public readback, with private case details excluded |

These roles are responsibilities to fill, not appointments. Never infer consent, independence, demographic attributes or regulator affiliation from a prospect list.

## Browser and AI-client participation

Start at https://councilof.ai/working-groups/ and the existing forum https://github.com/CSOAI-ORG/councilof-ai/discussions. Each document has an email alternative. Verify actual delivery before treating it as operational support.

The existing MCP endpoint is https://councilof.ai/mcp/free. A resource-capable client can list/read https://councilof.ai/working-groups/catalog.json. A prompt-capable client can request working_group_review with the exact public documentId. It returns the shared blank review with source pin, competence/conflicts, dissent and permission sections. Evidence stays local until the participant chooses a submission route. Tools-only hosts can use the browser tracker. Record qualification per host and version; do not assume support across all AI platforms.

The local stdio preview, remote resource/prompt, browser register, generated HF kit and frozen Kaggle notebook have distinct delivery states. Consult the release receipt. Generated files do not establish deployment. The loopback SQLite lab remains a feasibility exercise, not a public forum.

## Accessible and independent participation

Offer asynchronous plain-text review, a no-GitHub email route, flexible times, clear language and a private accommodation channel. Ask which language, format or support participants want; do not infer needs or protected traits from names, photographs or profiles. Independent researchers can demonstrate competence through public work and a small reproducible task; institutional affiliation is not required.

Test the actual journey with consenting participants using different access methods. Record task completion, friction and unresolved barriers with permission. Automated WCAG and 320px browser checks do not establish usability for every demographic or assistive technology.

## Halt-latency evidence

Record revocation issue time, receipt at each enforcing boundary, last admitted action, cancellation acknowledgement, last observed action completion and independently observed external effects. Bind events to delegation/chain IDs and exact source/run configuration. State clock domain, synchronization uncertainty, observation window and missing events.

Report propagation delay, admission cutoff and in-flight completion/effect delay separately. Unknown terminal actions or effects are INCONCLUSIVE, not zero latency. Cancellation acknowledgement alone does not prove child work or external effects stopped. Synthetic controls qualify the method only; a production bound needs the actual host integration, concurrency envelope, fault conditions and accepted service target.

Use the existing authority and SDK lanes for admission, cancellation and effect reconciliation. The public tracker and MCP prompt confer no execution permission.

## Evidence needed to call a group operational

Retain accepted editor/moderator duties, verified submission delivery, conflicts and publication permission, an independent review with dissent, a reasoned human decision, an exercised appeal route and participant feedback. Prospect research, prepared messages and software tests cannot substitute for these records.

Regulator/standards liaison uses a verified official route and an explicitly approved message. Membership or subscription is not endorsement. New spending, employment terms, rights transfers and public membership claims need the responsible person's actual decision.
