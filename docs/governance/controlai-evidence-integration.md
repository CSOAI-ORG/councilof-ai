# ControlAI research evidence integration

This candidate turns dated ControlAI research into a source-linked review pack in the existing Public Watchdog tracker. It provides 40 public source summaries, 12 policy-to-evidence review tasks, eight collaboration leads and six claim records. The canonical source is `council-os/working-groups/research/controlai.json`; generated mirrors must not be edited independently.

The useful connection is evidence and review. ControlAI's website is https://controlai.org. No supported ControlAI software API, SDK, blanket source-content licence, partnership or endorsement was established. The implementation therefore makes no credentialed connection or automatic external submission. Source contents are not relicensed by this repository's MIT licence: only our original summaries and code are distributed.

## Use now

From the checkout with its locked dependencies installed:

```sh
node scripts/working-groups/check-research.mjs --as-of 2026-10-30
node --test scripts/working-groups/research.node-test.mjs
node scripts/harness-x/render.mjs --check
python3 -m http.server 8765 --bind 127.0.0.1 --directory public/working-groups
```

Open `http://127.0.0.1:8765/controlai.html`. Search ControlAI in the native Watchdog document tracker. The lightweight tracker links the same pack, and the JSON download carries the complete dated register. Hugging Face candidate files and the offline Kaggle notebook are generated by the existing distribution renderer. These files are usable locally; platform publication follows the existing release lane.

The local stdio MCP preview now exposes `working_group_research` with `packId: "controlai-20261030"` and a required `asOf` date. It returns the source pack and usability results without network access or writes. Use `distribution/working-groups/mcp-client.template.json` with an absolute checkout path after installing dependencies. A local protocol test does not establish registration or compatibility in every client.

## What the six records demonstrate

| Record | Meaning | Boundary |
| --- | --- | --- |
| CL01 | UK bill status from official parliamentary sources | Proposal and future stage; not enacted law |
| CL02 | Completed public ControlAI–Apart critique event | Organiser report; not a present invitation |
| CL03 | Retained run of four existing revocation controls | One local synthetic process, not production shutdown |
| CL04 | Deliberately unsupported endorsement sentence | Synthetic negative control, never authentic evidence |
| CL05 | Stale legal-name claim retained | Superseded; must not be silently deleted |
| CL06 | Dated legal-name correction | Registry statement, not an audit of filed facts |

The checker validates structure, references, local artifact bytes, dates and runtime scope. `READY_FOR_HUMAN_REVIEW` means the record has the required fields within its review interval. It is not a verification of the claim's truth, source accuracy, reviewer independence, legal compliance or AI safety. Dated checks at or after 6 November require review again. Use the actual reliance date, not the example date. External source SHA-256 values remain null because the research did not retain the exact source bytes; the local observation file has a genuine digest.

Replay the retained runtime trace:

```sh
node scripts/hitl/revocation-latency.mjs --check evidence/research/controlai/revocation-observation.json
```

The expected exit code is 1 because the retained controls intentionally include two FAIL outcomes. Re-run `--run-fixtures` to a new output file for a new observation; do not overwrite the earlier evidence. Expected control sequence: PASS, FAIL, FAIL, INCONCLUSIVE. The original runner, its frozen method and GSPC grader retain their existing ownership. This integration adds no measured axis or general safety score.

## Review and correction

Use the existing COAI-WG-001 review draft route. Record the exact pack version, source dates, any inaccessible source, proposed correction, reviewer identity/competence/conflicts and dissent. Preserve earlier records through reciprocal supersedes/supersededBy links; a new factual observation needs a new date and retained evidence. Source snapshots, if subsequently captured with appropriate rights, require a separate capture contract rather than invented hashes.

Each crosswalk is still `UNTESTED_PROPOSAL`. Its acceptance question describes work to evaluate. Mapping a draft bill to an existing control does not establish compliance, and a local revocation drill does not establish that production effects stop. Human authority, host binding and execution retain their existing service boundaries.

For a real collaboration pilot, a separate named reviewer must inspect the packet, reproduce a local check, reject the unsupported fixture, identify the superseded record and record a decision or correction. A proposed comparison can measure their accuracy and time against source links alone. No recipient, review session, acceptance result or causal improvement is invented. Recheck official policy stages and event entry terms before any future external submission.
