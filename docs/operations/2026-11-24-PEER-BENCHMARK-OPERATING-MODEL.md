# Council of AI / CSOAI — competitor intelligence, organisational business plan and operating model
**Research cut-off: 24 November 2026 UTC.** **Decision grade: comparative intelligence + testable operating proposals, NOT adopted governance, forecast assurance, verified buyer demand or regulator endorsement.**

## Executive decision

**Concentrate on the portable evidence/authority/effect interface between AI products rather than building another full observability SaaS, an unauthorised certifier or MEOK foundation model from scratch.** Keep public research/open verification useful; sell properly scoped evidence integration and purchaser-authorised agent-action pilot delivery. The prospective defensibility is independently reproducible, source-corrected *change-over-time* claims and real downstream effect receipts, **if** delivered and independently accepted. Being the only provider or a first mover has not been established.

**Canonical roles**
- **GSPC** — measurement instruments, pinned banks, method/uncertainty/denominators, longitudinal qualifiers; 34 public axes are not 34 independently validated AI benchmarks.
- **MEOK** — candidate hypothesis, model/provider routing, bounded orchestration and proposed adaptation; private runtime operation is a separate acceptance gate.
- **Layer-0 / evidence fabric** — canonical byte provenance, inclusion/OTS/signature verification, signed-card and root gates; signed truth is not presumed.
- **Human Council / H.I.M. / WGs** — person-authenticated skill, informed explanation, independent review and disagreement, with actual delegated authority; directories of opportunities are not staffed reviewers.
- **CouncilOS** — customer/operator workflow and reviewable status views, never an alternate authority oracle.
- **SovSpace / lab** — isolated simulations, digital twins and fault injection; synthetic results never become production measurements or customer effects.
- **Commercial / finance** — accepted buyer scope, invoice and actual independently reconciled non-self money, separate from package downloads and x402 self-tests.

## What to learn from their *code and operations*, not just brand names

1. **Ingest → queue → storage → compute → index** (Langfuse): decouple API acceptance from heavy indexing and measurement; use bounded queue/retry/dead-letter and per-run source IDs; don't make root signing depend on indexing latency.
2. **Dataset → experiment → scoring → versioned comparison** (Phoenix, Inspect): freeze bank, model route, scorer and environment *before* running; matched pairs and uncertainty, no optimistic cherry-picking; reproducible offline control before GPU spend.
3. **Target → attack orchestration → response → independent scorer** (PyRIT): deliberately separate generation, attack execution and evaluation; no evaluator sees answer-bearing metadata; record prompt-injection leakage controls.
4. **Developer-first test-as-code** (DeepEval, Promptfoo): publish minimal working client, sensible defaults and CI gates; product adoption is easier when one developer can reproduce a result without learning GSPC's 34 axes.
5. **Durable process, not optimistic orchestration** (Temporal): retries bounded by cost/idempotency, event history and suspend/resume for actual human authorisation; stale approval must be rejected by executor each time.
6. **Common telemetry vocabulary** (OpenTelemetry): use OTLP for application spans; keep a separate signed evidence object that explicitly identifies which observations are independently sourced and which are self-reported.
7. **Enterprise discovery/traceable control register** (ModelOp, Credo, Holistic): maintain bounded agent inventory and policies; signal when risk/evidence becomes stale after version changes; distinguish continuous monitoring from certificate claims.
8. **Instrument metrology** (NIST and Council #4763): measure grader drift, false alarms and delays; frozen known-answer check standards; **25/25 synthetic tests passed on both Macs 23 Nov** but this is not a calibrated operational grade.
9. **Model merging is not evidence merging** (MergeKit): never use a merged model as independent reviewer or cryptographic proof; paired held-out tests must show benefits without creating correlated failure.
10. **Independent downstream effect** (Council's hypothesis): join upstream trace, scoped authority, tool executor, receiver-origin response, correction and retest. Each absent link is explicit `NOT_MEASURED`/hold.

**Preferred wedge:** one scoped and authorised agent action, two releases (before/after), proof of what changed, independently observed allowed/denied effect, and a real authorised buyer acceptance. This is a smaller, sharper selling proposition than '34-axis safety platform' or invented standards certification.

**Public self-service:** free verification + fixed-scope paid evidence support; x402 is an optional payment rail, not a substitute for customer agreement or settlement. Preserve commercial independence, privacy and explicit consent. Don't turn worker output or private review records into public marketing data automatically.

### Price and unit-economics hypotheses (not actual accounts)

`£3,000` scoped pilot price is a **discovery hypothesis** from earlier planning, subject to signed scope and VAT/insurance/legal review. Illustrative direct delivery assumptions only: 18 engineer hours × £60 = £1,080; 4 independent reviewer hours × £75 = £300; compute/storage £120; onboarding and reproducibility £150. **Total illustrative variable cost £1,650**, contribution **£1,350 (45%)** *before tax, overhead, legal, insurance, customer acquisition, rework and payment fees*. If accepted scope requires 35 engineer hours at the same rate and other costs unchanged, variable costs rise to £2,670 and contribution falls to £330 (11%). Nothing in this model represents actual cash, a customer contract, realised wage cost or pricing power.

Target funnel for first 30 days, **proposed, not completed**: 5 qualified buyer conversations → 2 scoped feasibility reviews → 1 written pilot scope. No booked pilot or four commercial customers should be inferred. Pilot success requires customer-controlled sandbox access and actual signed authorisation, not synthetic outputs.

### Daily / weekly / monthly operating ritual

- **Every day 08:00 UTC — observer heartbeat:** run `scripts/operating_heartbeat.py` (GitHub-only source). Store timestamped immutable artifact, triage holds and unknowns; no automated GitHub merges, releases, billing, emailing or external agent effects. This is an *additional evidence view*, not a declaration of organisational safety.
- **Every day 08:20 — release/measurement:** choose at most three high-leverage blocked matters; root/freshness remain real gate holds, identify their precise sources and next measurable qualification. Avoid synchronising PR while gate checks are active.
- **Every day 08:40 — product/commercial:** one concrete customer pain/observable outcome and next authorised customer action; mark unanswered/unqualified as unknown. Preserve private contacts in approved CRM, never CI artifacts.
- **Weekly 30–45 min** review source changes, grader calibration, incident recurrence, error correlation, product adoption funnel, accepted receipts, cash, community review staffing, model/runtime change impact.
- **Monthly** risk/claims register review, source licensing and security inventory, pricing actual-cost re-estimation, compensation/conflict disclosures and privacy retention review. Release a transparent public methodological summary only after review.
- **Escalation:** severe security/privacy incident → named human/security owner → relevant systems held; never let score or PR automerge decide legal authority, identity, settlement or external effect.

### Measured scorecard definition (default UNKNOWN, never 0)

- **Evidence:** total `qualified L2` reproducible evaluations; percent full source lineage; per-axis bank freshness age (measurement time vs retrieval time); grader check-standard alarms vs false-alarm rate under controlled null.
- **Effect:** number of uniquely recipient-origin verified permitted and prevented actions; unknown effect denominator; correction-to-publication intervals with missingness/censoring.
- **Governance:** number of genuinely accepted/authorised reviewers (private verified register), independently reviewed decisions, unresolved disputes and aged evidence.
- **Commercial:** number of qualified buyer conversations, proposed scopes, *signed* scopes, accepted deliveries, invoices, actual reconciled non-self settlements and gross margin net of delivery costs. No vanity conversion.
- **Engineering:** successful CI, latest branch freshness, failed deploys, RTO/RPO tested, independent readback, scoped execution blocks, protected gate exceptions and their rationale.

### 90-day execution chain with externally verifiable exits

**Days 0–14 — consolidate:** keep existing #4697 root and #4754 freshness holds visible; run actual GSPC grader calibration against independent frozen check standards (the simulated drift monitor is not sufficient). Provide read-only OTel-to-evidence event mapping. Consolidate marketing claims. Deliver one public reproducible verifier with a user-run exact-byte replay. **Exit:** a second environment reproduces source and limitations, no false root promotion.

**Days 15–30 — pilot readiness:** qualify named human reviewer and customer sandbox owner *if they accept*; freeze one allowed-action tool, explicit negative-control matrix, all revocation states, receiver-origin readback; confirm operational MEOK bridge authority rather than relying on a chat proposal. Offer buyer scope privately. **Exit:** one signed written pilot scope **or explicit no-customer gap**; no fabricated engagement.

**Days 31–60 — evidence continuity:** repeat the same case after pinned runtime/model/tool revision, show which evidence remains applicable and which is stale, re-evaluate grader. Integrate adapter with one of Inspect/Phoenix/OTLP/Promptfoo using its actual licence. Run an independently scored merge candidate only if weights and compute permits. **Exit:** matched two-release verification with independent receiver, or failure document showing missing trust chain.

**Days 61–90 — revenue/scale:** qualify who paid and accepted a bounded service; actual contribution margin by case; create self-service free verify and paid scoped-recheck flow; publish consented methods/results without exaggerated certification. **Exit:** documented customer-accepted case and realistic unit economics **if obtained**, otherwise product revision, not fictional bookings.

### The operational flywheel (preserve failure evidence)

```
Source change or customer requirement
→ canonical source digest + classification + responsible owner
→ preregistered measurement / threat & negative controls
→ GSPC / grader calibration / uncertainty
→ signed evidence candidate with scope and dependencies
→ actual qualified human decision when required
→ executor validates scope + revocation at effect time
→ independently observed downstream effect and reconciliation
→ customer/reviewer acceptance OR disputed/unknown
→ source-dependent recheck or correction
→ bounded reusable product example / qualified commercial lead
```

**Stop conditions:** root gate fails; unstaffed human decision; missing executor check; unknown receiver; privacy/rights conflict; invalid provenance; source timestamps invented; conflicting denominators; uncertainty omitted; revenue not reconciled. No autonomous bypass.

## Read-only operating heartbeat implementation

The companion `scripts/operating_heartbeat.py` checks named PRs/workflows and records source-corrected statuses, with GitHub URLs. It distinguishes master-branch CI success from PR/nonmaster success and unattributed run branches, so a successful research PR never masquerades as a deployed master workflow. It **does not** inspect private bank/CRM/human authority/effect or live website and explicitly marks these `NOT_MEASURED`. Synthetic and source-only CI success cannot become a green organisational certification. Unit/negative controls are in `scripts/test_operating_heartbeat.py`, and `.github/workflows/organisation-operating-heartbeat.yml` uploads daily snapshots, reporting unknowns without silently promoting an artefact.

**Guarding against false reports:** root/freshness PR open = HOLD; source fetch fail/stale workflow = UNKNOWN or review; workflow pass = CI source only; PR merged = merged source only, not deployed; customers, actual staff, revenue and recipients never inferred. Never expose GitHub tokens, external customer data or private review records in artifacts.
