**Working paper: 24 November 2026. Status: PROPOSED, not adopted, staffed, externally certified or customer-accepted.** Vendor observations below are grounded in public company documentation, not exhaustive external source audits. ## 1. Executive thesis and prior work

The opportunity is an **independently inspectable, change-aware evidence and authority lifecycle for consequential AI agent actions and maintained AI claims**. GSPC measures; Council OS explains evidence; MEOK prepares bounded actions; an actually authenticated human with jurisdiction decides; a qualified executor acts; a distinct observer and receiver establish outcomes; Watchdog triggers rechecks; Academy trains people. Each step has different facts and owners. Never use a signed timestamp, code merge, 33 role labels, or simulated council vote as a substitute for human authority or independent measurement.

The existing repo already contains extensive strategy and commercial work:
- docs/REVENUE-LOOPS.md: verification free, metered evidence assembly/cadence and x402, not the sale of a GSPC grade.
- docs/commercial/AGENT-AUTHORITY-PILOT-LAUNCH-KIT-20261120.md: a single buyer-owned sandbox action, consent, negative tests, independent effect, private SOW and buyer acceptance; expressly NOT LAUNCHED.
- docs/governance/council-ai-agent-operating-controls-v0.1.md: operating policy is PROPOSED; it has not become an adopted charter merely because a tool built it.
- docs/competitors/COMPETITIVE_LANDSCAPE_2026.md: **historical brainstorm, not an approved marketing source**. Its hard-coded SaaS prices, 348 compliance MCP servers, “33-agent BFT verification” and unqualified certification advantage are not verified current facts.
- MEOK–Council C1–C7 draft PR #4703: source bridge works independently on M2 and M4; installed M4 user tool registration, actual authenticated human authority, qualified private Company-case receiver and independently acknowledged effect are distinct open tests.
- HF GSPC–MEOK release: immutable revision a533a34ccb9f428d0fb3dd6b9f1f831c5f43d1c6 contains 26 labelled research records with a manifest independently matched to protected GitHub source on both machines; it is not peer review or model certification.

The public GSPC 34-axis board has 14 model-comparison axes and **zero statistically separated leaders** in the current read. Governance itself discloses wording-derived label leakage: 225 of 237 bank labels can be predicted by a simple wording-only baseline. A successful daily read is not a new measurement. The claim register's 99 claims across 28 subjects and five subjects with due execution unverified must be presented as source-declared, not manually completed.

### Internal source reuse: avoid rebuilding existing adapters

The current Council repository already has a useful interoperable foundation:

- `packages/otel/README.md` and `packages/otel/route_receipt.py` implement an optional, fail-closed OTLP/JSON GenAI routing receipt with digest/trace IDs and **no copied prompts, tool arguments or responses**. `functions/mcp/_otel.ts` distinguishes HTTP door/transport observations from actual tool outcomes. **Use these existing contracts first**; do not create a second tracing event model or infer tool success from HTTP 200.
- `packages/evidence-fabric/RECEIVER-ADAPTERS.md` documents implemented **offline local projections** for **Langfuse, Alan Turing Institute TEA and Moonshot**. It explicitly does **not** establish any real receiving-party import/acknowledgement. Qualification should begin with an authorised receiver-owned synthetic test, pinned API/schema version, redacted fields, exact-request digest, authenticated ACK and later receiver GET/reopen. Keep source `csoai.evidence-event/0.1`.
- New candidates should be admitted only if the present adapters cannot express the required evidence. Prioritise missing integration tests over generic package proliferation; any commercial integration first requires licence and personal-data handling review.

**Cross-team owner task:** science signs off whether local evidence records actually prove the claim; MEOK owner qualifies receiver/account/scope; evidence-fabric owner tests existing adapter; human authority steward confirms independent principal; commercial owner obtains buyer/SOW; SRE retains exact deployed receipts. None may report `RECEIVER_ACCEPTED` without a real external acknowledgement.

## 4. Operating heartbeat: roles, daily source truth and gates

The proposed technical pilot in scripts/operations/council_heartbeat.py reads five fixed public sources and selected public GitHub PRs with bounded GET requests, source hashes and actual observation time; it stores a JSON and Markdown pulse. It does not make payments, publish model scores, obtain customer data, infer signatures, approve people or execute tools. Tests independently cover stale clocks, invalid/missing data, corrupted manifest digest, misleading root signatures, unsafe URL and authority non-promotion. The scheduled GitHub Action is a **proposal** until a protected merge and a successful workflow run proves it is operating.

A GitHub issue is not a customer. A 402 challenge is not revenue. A publisher-signed evidence card is not peer-reviewed measurement. A public dashboard cannot read a private CRM, and may not invent its counts.

## 5. Commercial thesis and stage-gated offers

Initial wedge is **one buyer-authorised sandbox agent action** for an AI engineering/security lead who can name the write-capable tool, desired effect, legitimate human approver, observable receiving system and forbidden controls. Deliver a bounded written scope, deny/replay/revoke tests, source hashes, a separate observer, a truthful limitations report and buyer acknowledgement. Private quote anchors require actual company approval, time/cost calculation, signed contract and no default public SaaS prices.

Other candidate offers: change-aware evidence maintenance (only with staffed alerts), portable evidence packs (not certification), and permissionless x402 evidence assembly (outside buyer payment must be independently reconciled). Free verification should continue; recurring contracts should require real value and service capacity.

**Private sales states:** RELEVANT_ENQUIRY → QUALIFIED_BUYER → WRITTEN_SCOPE → SIGNED_SOW → AUTHORISED_TEST → INDEPENDENT_REVIEW → DELIVERED_REPORT → BUYER_ACCEPTED → INVOICED → RECONCILED_PAID → RENEWED_OR_CORRECTED. Do not infer transitions from marketing content, Github downloads, self-wallet settlements, synthetic principals or model opinions.

## 6. Standards and audit boundaries

The NIST [AI RMF Playbook](https://airc.nist.gov/airmf-resources/playbook/) offers Govern/Map/Measure/Manage control organisation. The [IETF RATS architecture](https://datatracker.ietf.org/doc/html/rfc9334) explicitly separates attester, verifier and relying party: useful for Council's publisher/proof/receiver distinctions but not a claim that a GSPC card is a hardware remote attestation. SLSA provenance, Rekor inclusion, OTS and Ed25519 must be independently tested with exact source scope. Neither an AI judge nor a Byzantine simulated referee creates a named human decision.

**Explicit operating states:** DISCOVERED, SOURCED, TESTED, REVIEWED, ADMITTED, DEPLOYED, INDEPENDENTLY_READ_BACK, HUMAN_APPROVED, EFFECT_OBSERVED, RECEIVER_ACCEPTED, BUYER_ACCEPTED, PAID, CORRECTED/RETIRED. These are independent predicates, not a single automatic workflow. Each step requires an actual record and qualified actor.

**Current known holds:** no real installed MEOK↔Council action chain or newly authenticated human; no established private buyer/receiver acceptance; no independently accepted model-comparison winner. This document creates no authority, contract, appointment or customer.
