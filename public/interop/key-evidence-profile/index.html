Key and evidence checks you can reproduce.

This evidence-only profile reproduces a pinned reference implementation and makes three additional integration assumptions explicit: the intended subject must match, and lookup evidence and attested signing time must not come from after the evaluation instant.

21 reference outcomes preserved; three additional cases distinguished. The separate input, boundary and CLI suite ran 23 test methods. These are different denominators. The results are synthetic fixture evidence, not a production safety rating or permission to execute.

Run it yourself

Extract the archive, then use Python 3.11 or newer in an isolated environment. Dependency installation needs network access; the checks themselves make no network requests.

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python upstream/trust/key-evidence-states-v0/check.py
.venv/bin/python test_profile.py
.venv/bin/python replay.py --check
.venv/bin/python profile.py example.json

The CLI returns JSON with execution_authority: false. Exit 0 means evidence passed this profile; 1 means failed; 2 means could not determine; 3 means upstream integrity could not be established. The policy and trust anchors must come from the relying party’s trusted configuration.

Credit and scope

The reference implementation comes from AI KR community-group PR #25, pinned to commit a42fb08. Its README credits Nicholas Templeman’s proposal. Upstream files remain unchanged and their licence notices are included.

This is a Council discussion profile. It is not a W3C Recommendation, an adopted group requirement, an independent cryptographic implementation or a production authority service. A historical pass does not establish current authority. Hashes establish byte correspondence when compared with a trusted reference; they are not signatures or external timestamps.
