### Numeric Canonicalization Issue

The remote signer (JavaScript, `/api/board-sign`) converts `float 1.0` → `int 1` during JSON serialization. Python's `json.dumps` preserves `1.0` as `"1.0"`. This means 10 of 36 cards have IDs that only verify when the body is pre-processed with JS-like numeric normalization:

```python
def js_number(val):
    if isinstance(val, float) and val == int(val):
        return int(val)
    # recursive for lists/dicts
```

Affected cards have `uncertainty_95_wilson` values containing `1.0`. The 26 unaffected cards have no integer-valued floats.

**Impact:** Independent Python-only verifiers will see 10/36 ID mismatches unless they apply JS canonicalization. This must be documented in HOW-TO-VERIFY.

### Body State Discrepancy

All 36 signed cards have `body.signature_state = "STAGED_UNSIGNED"` despite having a valid outer Ed25519 signature. The outer wrapper proves the card was signed, but the body field was not updated to reflect this. This is a metadata inconsistency, not a signature failure.
