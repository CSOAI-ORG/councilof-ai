01 Memory Architecture 3-TIER HIERARCHY

SOV3 memory is partitioned into three temporal tiers. Each tier has different retention rules, retrieval semantics, and persistence guarantees. Episodes flow downward from short to long as their importance and care weight grow — only the most cared-about moments survive the consolidation to permanent ledger.

TIER 1 · SHORT

Working Context

→ Live session buffer ←

Current conversation thread. All messages, tool calls, intermediate reasoning. Ephemeral — flushed at session end unless promoted. Lives in RAM + Postgres current_session table.

04 Recall Patterns QUERY → TOP-K

When the sovereign needs to remember, it does not grep. It runs the recall pipeline: vectorise the query, search across all three tiers, rank by care-weighted semantic similarity, return the top-K episodes with provenance. The whole flow is ~80ms from prompt to episode previews.

01
🔍
Query Ingest
User prompt parsed. Embedding model (nomic-embed-text, 768-dim) computes query vector. Care-context extracted from session state.
# semantic search
q_vec = embed(query)
care_ctx = session.care_state
02
🌐
3-Tier Search
Vector similarity across Tier 1 (working), Tier 2 (recent 1K), Tier 3 (SIGIL ledger). Top-50 candidates per tier merged.
# cascade
candidates = []
candidates += search_t1(q_vec, k=50)
candidates += search_t2(q_vec, k=50)
candidates += search_t3(q_vec, k=50)
03
⚖️
Care-Weighting
Each candidate scored: score = sim × (0.5 + 0.5 × care_weight). High-care episodes dominate ranking. Trivial memories demoted.
# weighted score
score = sim * (0.5 + 0.5 * care)
# decay
final = score * exp(-age/τ)
04
🎯
Top-K Return
Top 5–10 episodes returned to the LLM context, prefixed with provenance + SIGIL digest. Whole call: ~80ms.
# return
top_k = 5
result = rank(candidates)[:top_k]
ctx = format(result, sigil)
