2. Cycle Anatomy — What One OOWM Cycle Looks Like

Cycle = 7 Stages × 33 Agents × Hash-Chained SIGILs

  1. Stage 1 · Jagrat (Waking) — opus issues the cycle intent. Care-weight ≥ 0.95 required. SIGIL H|opus|sov3|cycle-511-intent.
  2. Stage 2 · Svapna (Dreaming) — sov3 derives the substrate state (Mamba 16-dim + MoE weights + ZAMBA context). 3 SIGILs.
  3. Stage 3 · Prana (Inquiry) — hermes dispatches 5-15 sub-queries. Each carries a separate SIGIL.
  4. Stage 4 · Vichara (Discernment) — jeeves + kimi + orion + riri + hourman execute in parallel. 5 SIGILs minimum.
  5. Stage 5 · Karma (Action) — tool calls, file writes, deploys. Every action SIGIL-signed.
  6. Stage 6 · Sthiti (Ground) — horus watches. Care-weight re-asserted. SIGIL ledger closed.
  7. Stage 7 · Turiya (Meta-Monitor) — mini-batch OLM update. New care-weights published. Cycle digest emitted.

A typical cycle emits 23-47 SIGILs and produces ~1.27M episodes of training lineage (649M / 511 = 1.27M avg).

Why 1.27M episodes per cycle?

Each OOWM cycle emits ~1 SIGIL per agent-action. With 33 agents, 7 stages, and an average of 5.5 sub-actions per stage, you get ~1,271 distinct actions per cycle. Each action produces a lineage record (input → model → output → care-weight → next-action). Multiply by 511 cycles = 649M lineage records. This is provenance, not just logs. Every record is hash-chained to the SIGIL ledger and includes the agent, model, jurisdiction, and care-weight of its creation.
