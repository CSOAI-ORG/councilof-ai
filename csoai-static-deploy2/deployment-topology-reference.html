3. SIGIL Attestation Gateway

Every request flowing between layers passes through the SIGIL Attestation Gateway:

Gateway PointWhat Happens
L5 → L4 (public → governance)Request validated. SIGIL receipt created. BFT council consulted for governance-sensitive actions.
L4 → L3 (governance → federation)BFT approves tool invocation. SIGIL receipt for MCP call. Ring boundary checked.
L3 → L2 (federation → inference)Data sanitised before model exposure. Inference routing determined (sovereign vs frontier).
L2 → L1 (inference → custody)Output stored in escrow with per-record DEK. SIGIL receipt for storage. RFC3161 timestamp.

6. Federation Discovery Protocol

New AUKUS partner deployments discover the DEFONEOS federation via a well-known manifest:

GET /.well-known/defoneos-manifest.json

The manifest contains:

  • version — DEFONEOS version (semver)
  • mcps[] — List of active MCP servers with IDs, names, trust rings, and health status
  • bft_council — BFT council status: active agents, quorum thresholds, current care-score
  • sigil_endpoint — SIGIL verification endpoint for receipt validation
  • escrow_public_key — Escrow Ed25519 public key for release verification
  • ots_anchors[] — Bitcoin OTS anchor points for ledger verification
