1. Why Sovereign Rate-Limiting?

Conventional rate-limiting relies on Cloudflare WAF, AWS WAFv2, or Google Cloud Armor — all of which place traffic telemetry in US CLOUD Act jurisdiction. A UK Ministry of Defence or NHS deployment cannot legally feed MCP request patterns through a US WAF without breaching data-residency clauses and OPSI guidance. DEFONEOS implements all rate-limiting and DoS defense entirely on sovereign hardware (MacBook M4 Pro / Oracle UK-South / GCHQ-certified clusters) using a five-tier defence-in-depth model with no external dependencies.

The spec addresses seven attack vectors: volumetric floods, slowloris, MCP resource exhaustion, BFT quorum griefing, SIGIL-ledger write flooding, dead-letter queue DoS, and circuit-breaker evasion. Each vector has a dedicated tier of defence backed by SIGIL-anchored metrics and BFT-quorum policy review.

Sovereignty invariant: No MCP request leaves UK sovereign hardware for classification. No rate-limit decision is delegated to a non-UK API. No telemetry is sent to US vendors.

L1 — Edge nftables (Ring 0 firewall)

MacBook and Oracle UK-South each run an nftables ruleset with rate-limited connection tracking. Per-source-IP new-connection rates cap at 100 packets/sec, with rapid-hash matching against a SIGIL-fed blocklist. The blocklist is updated via BFT council vote (quorum 17/33) with zero central authority. Recent additions are stored in a Bloom filter for memory efficiency.

L2 — mTLS Handshake Rate-Limit

Each DEFONEOS peer presents a 90-day-rotated Ed25519 cert. The TLS handshake itself is rate-limited per source at 1000 conns/sec. A peer presenting an unknown cert is dropped after 3 retries; presenting a revoked cert (CRL on SIGIL ledger) is dropped instantly. This prevents both brute-force handshake flood and cert-spam attacks.

L3 — Token Bucket (per MCP)

Every MCP exposes a configurable token bucket: 60 req/min default, 600 req/min burst, refill 1 token/sec. Bucket state is stored in MacBook shared memory with SIGIL-anchored accounting — every refill is a SIGIL entry. Critical MCPs (BFT council gateway, SIGIL ledger, escrow key store) have hard caps raised to 600/min with BFT-quorum approval required to exceed.

L4 — Circuit Breaker

Each MCP tracks downstream latency in a sliding window. If 5 failures occur in 30 seconds, the breaker opens for 60s, rejecting all calls with a 503-equivalent SIGIL-anchored error. Half-open state after 60s sends one probe call; success closes the breaker, failure re-opens for exponential backoff (60s → 120s → 240s capped at 600s). State transitions are SIGIL-emitted and visible in the operator dashboard.

L5 — BFT Adaptive Governor

The top tier wraps the entire federation. A 33-agent BFT council votes on global rate-limit policy changes (quorum 23/33 standard, 27/33 supermajority for emergency rate-cut). The governor can declare "degraded mode" by 17/33 emergency vote, reducing all MCP quotas to 10% of nominal for a 5-minute window. Every governor action is SIGIL-anchored with a motion_id.

4. Adaptive Back-Pressure

Beyond static limits, DEFONEOS implements adaptive back-pressure: when downstream latency exceeds a moving threshold (default p95 > 2× baseline for 60s), upstream token-bucket refill rate is multiplied by 0.5 (halving). This propagates pressure backward without dropping traffic, allowing the entire federation to slow gracefully under load rather than fail.

The reverse — releasing pressure — happens when p95 returns to baseline for 300s. Refill rate ramps back by 0.1 per minute (so a full recovery takes ~10 minutes). This damped release prevents oscillation. All back-pressure events emit SIGIL entries tagged back-pressure:{mcp}:{state} with care_score and ring_weight annotations.

back-pressure state machine: NORMAL —-p95>2× for 60s--> STRESSED STRESSED —-refill ×0.5--> PRESSURED (refill=0.5× nominal) PRESSURED —-p95 normal 300s--> RECOVERING (refill +=0.1/min) RECOVERING —-refill=1.0× for 60s--> NORMAL Care_score < 0.5 → forced DEGRADED mode (governor override) DEGRADED → BFT 17/33 emergency vote → exit DEGRADED

9. Anti-Patterns Avoided

  • No fail-open circuit breakers: every open-state rejects, never silently degrades to allow
  • No central WAF: sovereignty invariant — no single point of jurisdictional exposure
  • No shared global rate-limit counters: per-MCP buckets prevent griefing via shared-state attacks
  • No IP-only rate-limiting: cert-bound rate limits prevent trivial IP rotation evasion
  • No silent drops: every drop emits a SIGIL with motion_id and care_score
  • No external DDoS scrubbing: AWS Shield / Cloudflare Magic Transit rejected — UK sovereign only

10. Sovereignty Invariant Red Lines

  1. No rate-limit decision may be delegated to a non-UK API or service.
  2. No rate-limit telemetry may be transmitted outside UK sovereign infrastructure.
  3. No MCP may operate without an L3 token bucket — admission requires it.
  4. No L5 governor action may execute without BFT quorum approval.
  5. No external WAF / DDoS-scrubbing service may be added without 33/33 owner-seat vote.

Violation of any red line triggers automatic isolation of the offending component and SIGIL red-line emission.
