1. What this index is for

A buyer does not need another promise. A buyer needs a route from a requirement to an artefact, from an artefact to a hash, and from a hash to a live or owner-controlled verification step. This index is that route for DEFONEOS. It is a navigation and evidence schema; it is not a claim that a regulator, prime, or government department has accepted the product.

The index is organised into five domains: identity and governance, security and resilience, data and sovereignty, compliance and procurement, and operations and commercial proof. Each domain has named evidence classes with an owner, freshness expectation, verification method, red-line status, and next action. The 27 classes are an index design so a buyer can see coverage without confusing coverage with certification.

  • Evidence is either live, locally reproducible, or explicitly owner-gated.
  • Every public claim should point to a URL, a receipt, or a named human action.
  • Dagon assets are excluded; this index covers the public DEFONEOS surface only.

4. Evidence record schema

Every evidence record should be legible to a procurement analyst and a machine. The minimum record binds an artefact to a stable slug, a content hash, a timestamp, a responsible function, a freshness interval, and a decision boundary. When a record is not yet public, the index says owner-gated or deferred instead of filling the field with a plausible-looking value.

The schema deliberately distinguishes `status=verified` from `status=designed`. A designed control can be valuable in a pilot conversation, but it must not be presented as operational evidence until the buyer can reproduce the check or inspect a signed receipt.

6. Provenance and freshness

A static public page has two independent freshness questions: is the content still the intended content, and is the control still true in the buyer's deployment? SHA-256 answers the first. A scheduled control test, signed receipt, or buyer-side verification answers the second. The index never collapses these questions into a single green badge.

The current tick pattern stores page size, SHA-256, compliance alignment and red-line count in JSON. The public operator should re-run the page probes after every alias rotation and re-run control-specific tests on the cadence stated in the relevant specification. Seven-year retention is the policy for receipts in the design; it is not a statement that every historical receipt is externally archived by a regulator.

  • Content integrity: compare local and edge bytes.
  • Control effectiveness: run the control-specific probe.
  • Authority: record the human or council decision where required.
  • Freshness: expire evidence rather than silently carrying it forward.

7. Buyer diligence path

The recommended diligence path is a 30-minute first pass followed by a bounded technical workshop. In the first pass, the buyer reads the home page, this index, the operator handbook, and the readiness checklist. In the workshop, the buyer selects one data flow, one privileged action, one failure scenario, and one disclosure requirement. DEFONEOS then maps those four questions to evidence records and a pilot acceptance test.

No buyer is asked to accept a generic sovereign claim. The buyer chooses the jurisdiction, data classification, control framework and operational owner. The public pages show the reusable substrate; the pilot determines the deployment-specific evidence.

8. Commercial evidence without overclaiming

A buyer may ask for ROI, a procurement route, or a named pilot. The public index can point to the pilot ROI model and procurement tracker, but it must preserve the difference between an addressable opportunity, a weighted pipeline, a submitted bid, and an awarded contract. The same discipline applies to partnerships: AUKUS-compatible is a design posture; it is not a partnership claim without a signed letter.

The safest commercial evidence is a buyer-owned acceptance test with a measurable baseline: operator hours, incident response time, control evidence production time, or data residency verification. The public surface proposes the measurement; the buyer confirms the baseline.

  • No pipeline total is presented as booked revenue.
  • No prepared application is presented as submitted.
  • No compatibility statement is upgraded into a partnership statement.
  • No certification credential is implied by a page or a hash.

9. The anti-patterns this index defeats

  • **No screenshot assurance.** A screenshot is navigation, not a verifiable artefact.
  • **No one-number compliance.** Control coverage is mapped clause by clause; it is not a universal certification.
  • **No stale receipt.** A hash without a timestamp and freshness rule is incomplete evidence.
  • **No public/private mixing.** Dagon is not a public cross-link and is not part of this buyer index.
  • **No vendor substitution.** The buyer's own deployment evidence remains necessary.
  • **No red-line ambiguity.** Kinetic targeting and personal surveillance are outside the public DEFONEOS scope.

10. Next actions for a buyer

Start with three live anchors, run the listed byte and JSON probes, then send the four control questions to the owner-led workshop. The index is intentionally useful before a commercial conversation: it tells a technical team what to verify and tells procurement what remains a human decision.

For an owner, the next improvement is to attach every evidence class to a stable release receipt and keep the owner-gated list current. The correct goal is not a larger claim count; it is a smaller distance between a buyer question and independently inspectable proof.
