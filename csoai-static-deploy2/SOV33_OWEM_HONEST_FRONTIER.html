What SOV33 is NOT:

  • NOT A 1.6T / 100T / any T-parameter frontier foundation model
  • NOT A competitive world model at production scale (predictor is 16→32→16 toy)
  • NOT EWC with true gradient-of-log-likelihood Fisher (proxy estimate from weight magnitude)

8 · Honest caveats (the 5 things SOV33 cannot do today)

  1. Cannot match GPT-5 / Claude Opus 4.5 on MMLU-Pro / GPQA / SWE-bench — gap of ~50pp on MMLU-Pro, ~60pp on GPQA, ~60pp on SWE-bench. The sovereign-by-construction advantage does not include benchmark parity.
  2. Cannot do real-time inference at frontier speed — Qwen3-0.6B on Mac M2: ~50 tok/s · Qwen3-30B on M2: ~5 tok/s (too slow). SOV33-large v2 (30B-A3B MoE) at 3B active: ~20 tok/s on M2, ~80 tok/s on A100.
  3. Cannot fine-tune without GPU — QLoRA training needs A100/H100 for 30B+ models. Mac M2 supports 0.6B only (4.6MB adapters). Bigger builds need Kaggle free GPU or paid H100 time.
  4. Cannot prove "live swap preserves memory" without live endpoints — SOV33_OWEM_REALITY_2026-07-12.md is explicit: structural separation of concerns is real, but a live-swap invariance test was retracted as tautological.
  5. Cannot ship production to EU buyers without EU AI Act compliance — watermarking (tick 102), FRIA (tick 98), PMS (tick 95), CR_A readiness (tick 95), all in place. DEFONEOS-SEAL (tick 99) issues the credential.

Key findings from live data

  • Best overall: qwen3-precise:latest at 55.6% composite (strong MMLU + GSM8K)
  • Best MMLU: qwen3-formal:latest at 100% (n=10 sample, needs larger sample for confidence)
  • Best IFEval: tied qwen3:0.6b and qwen25-creative at 75%
  • Worst: qwen3:1.7b — paradoxically slower and lower than 0.6B on this task set
  • Critical gap: HumanEval is 0% across all models — 0.6B-class Qwen cannot generate correct Python functions from scratch
  • Latency: 0.6B-base is fastest at 2.4s median; 1.7B is 3.4× slower and lower quality on this test set

What this tells us about the sovereign adapter design

  • Adapter training improves MMLU and GSM8K (precise beats base 0.6b by 15pp composite)
  • Adapter choice matters (precise vs formal: 14pp MMLU swing, 37pp GSM8K swing)
  • Code generation needs a different base model (Qwen3-0.6B insufficient; Qwen2.5-Coder-0.5B or 1.5B worth evaluating)
  • The sovereign stack is competitive for knowledge tasks (MMLU, GSM8K, IFEval) but not for code
