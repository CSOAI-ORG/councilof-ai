What this dashboard decides

This page is the operating sheet for the first buyer reply. It prevents over-talking. The job is to convert a reply into one of six classes, choose one artefact, and set exactly one next action.

  • Classify before drafting. Reply class drives tone, proof object and CRM score.
  • If the reply is GREEN, ask for a dated validation slot. If AMBER, give one useful object. If RED, close gracefully.
  • Never send uncontrolled claims. Every response includes an honesty line where a certification, partnership, or clearance is not complete.
  • Keep all contact-note fields minimal: role, organisation, public email, buyer words, next action, consented meeting notes.

Escalation rules

Escalate only when the reply creates a real decision path. Otherwise keep the loop quiet and useful.

  • Escalate to pricing only when the buyer asks cost, budget, procurement or quote.
  • Escalate to technical validation only when the buyer asks integration, data, test, security, architecture or assurance evidence.
  • Escalate to owner-gated route when the buyer asks accreditation, clearance, DSP, CE Plus, DASA, DIANA or UKDI status.
  • Archive when the buyer says no route, no remit, no authority, or asks not to be contacted.

Internal triage QA before owner sends

Use these checks as a final gate. A reply that fails any check is held for rewrite rather than sent.

  • Does the first sentence answer the buyer's exact question rather than re-pitching the company?
  • Is there only one ask, and can the buyer answer in less than thirty seconds?
  • Does every proof claim link to a public page or clearly say draft, designed, illustrative or owner-gated?
  • Have all references to MOD, NATO, DASA, DIANA, DAIC, AUKUS or UKDI avoided endorsement language?
  • Does the reply avoid fear, urgency theatre, kinetic language and personal-surveillance framing?
  • Is the CRM next action a dated action owned by one person?
