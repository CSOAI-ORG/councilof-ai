2. Step 1 — SPF (Sender Policy Framework)

STEP 1 · SPF · 2 MINUTES
Authorise your email-sending servers to send from @nicholastempleman.co.uk

SPF is a DNS TXT record that says "these servers are allowed to send email from my domain." Mod procurement gateways (dstl.gov.uk, mod.gov.uk) check this FIRST. Without it, mail gets rejected before SPF=pass is even logged.

2.1 — Login to your DNS provider

Pick whichever you used to register nicholastempleman.co.uk:

  • Cloudflare → dash.cloudflare.com → nicholastempleman.co.uk → DNS → Records → Add
  • Namecheap → namecheap.com → Domain List → Manage → Advanced DNS → Add New Record
  • 123-reg → 123-reg.co.uk → Control Panel → DNS → Add
  • IONOS → ionos.co.uk → Domains → nicholastempleman.co.uk → DNS → Add Record

2.2 — Add this exact TXT record

# Type: TXT # Host/Name: @ # (or leave blank — means the apex/domain itself) # TTL: Automatic (300–3600 seconds) # Value: v=spf1 include:_spf.google.com include:spf.protection.outlook.com include:eu.mailgun.org include:amazonses.com -all # What this means: # include:_spf.google.com → if you send via Gmail # include:spf.protection.outlook.com → if you send via Outlook/365 # include:eu.mailgun.org → if you use Mailgun (for DEFONEOS bulk) # include:amazonses.com → if you use Amazon SES # -all → REJECT everything not on the list (hard fail)
Pick only the services you actually use. If you use ONLY Gmail + Outlook, the record is: v=spf1 include:_spf.google.com include:spf.protection.outlook.com -all. Extra include: statements do NOT hurt — they just broaden the allow-list. But DO NOT use +all (allow everything) — that defeats the whole purpose. ~all (soft fail) is acceptable but -all is what MOD gateways expect.

2.3 — Save and verify

Wait 60 seconds for DNS propagation. Then verify on terminal:

dig TXT nicholastempleman.co.uk +short # Should return: "v=spf1 include:_spf.google.com include:spf.protection.outlook.com -all"

Or use the web tool:

  • mxtoolbox.com/spf.aspx → paste nicholastempleman.co.uk → click SPF Record Lookup
  • Should show green check + the full record

3. Step 2 — DKIM (DomainKeys Identified Mail)

STEP 2 · DKIM · 15 MINUTES
Cryptographically sign every email you send so MOD gateways verify YOU sent it

DKIM is the cryptographic signature. Without it, even with SPF, MOD spam filters flag the email as "no signature = likely spoofed." With it, the email passes cryptographic verification and lands in inbox.

3.1 — Choose your sending service

Each email-sending service has its own DKIM key. You need ONE key per service. Pick whichever you use:

  • Gmail/Google Workspace → admin.google.com → Apps → G Suite → Gmail → Authenticate email → Generate new DKIM key → 2048-bit → Copy the TXT record value
  • Outlook/365 → security.microsoft.com → Email & collaboration → Policies & rules → Threat policies → DKIM → Enable for nicholastempleman.co.uk → Copy the two CNAME values
  • Mailgun → app.mailgun.com → Sending → Domains → nicholastempleman.co.uk → Click "Add DKIM" → Copy the TXT record value
  • Amazon SES → console.aws.amazon.com/ses → Verified identities → nicholastempleman.co.uk → DKIM → Enable → Copy the 3 CNAME records

3.2 — Example: Google Workspace DKIM (most common for solo founders)

# From admin.google.com DKIM page, you'll get a TXT record like: # Type: TXT # Host/Name: google._domainkey # Value: v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEAxYz7k9RtRj8bVxL4bPeG2hKlMnOpQrStUvWxYzAbCdEfGhIjKlMnOpQrStUvWxYzAbCdEfGhIjKlMnOpQrStUvWxYzAbCdEfGhIjKlMnOpQrStUvWxYzAbCdEfGhIjKlMnOpQrStUvWxYzAbCdEfGhIjKlMnOpQrStU...truncated-to-2048-bit-base64-string... # CRITICAL: Must be 2048-bit (not 1024). Google defaults to 1024 — explicitly select 2048 in the dropdown.

3.3 — Paste the DKIM record

# In your DNS provider, add: # Type: TXT # Host/Name: google._domainkey (or whatever selector your provider says) # Value: [paste the full p=... string] # TTL: 3600

3.4 — Wait, then verify

dig TXT google._domainkey.nicholastempleman.co.uk +short # Should return: "v=DKIM1; k=rsa; p=MIGfMA0GCSq...truncated..." # Or via web: # mxtoolbox.com/dkim.aspx → select the same selector
DO NOT SKIP DKIM. It is the single biggest determinant of whether your email lands in Inbox vs Junk. SPF says "I am allowed to send from this domain." DKIM says "Cryptographically, this email has not been tampered with." Both must pass for top-tier Inbox placement.

4. Step 3 — DMARC (Domain-based Message Authentication, Reporting & Conformance)

STEP 3 · DMARC · 3 MINUTES
Tell the world what to do with email pretending to be from your domain

DMARC ties SPF + DKIM together and tells receiving servers: "If an email claims to be from @nicholastempleman.co.uk but fails SPF or DKIM, here's what to do." Without DMARC, even passing SPF+DKIM still gets ambiguous handling at strict MOD gateways.

4.1 — Add the DMARC record

# Type: TXT # Host/Name: _dmarc # Value: v=DMARC1; p=quarantine; rua=mailto:nicholas.templeman@gmail.com; pct=100; adkim=s; aspf=s # Breakdown: # v=DMARC1 → DMARC version 1 # p=quarantine → send failing email to Junk (NOT p=reject — that risks false positives) # rua=mailto:nicholas.templeman@gmail.com → send DMARC reports to you (so you can see spoofing attempts) # pct=100 → apply policy to 100% of failing email # adkim=s → strict DKIM alignment (domain in DKIM signature must EXACTLY match From:) # aspf=s → strict SPF alignment (same)
Use p=quarantine, not p=reject. p=reject is what you set AFTER you've verified SPF+DKIM are working perfectly and you've seen no false positives for 2-4 weeks. Quarantine is the safe starting point. MOD gateways accept both, but quarantine is the standard for first-time senders.

4.2 — Verify

dig TXT _dmarc.nicholastempleman.co.uk +short # Should return: "v=DMARC1; p=quarantine; rua=mailto:nicholas.templeman@gmail.com; pct=100; adkim=s; aspf=s" # Or via web: mxtoolbox.com/dmarc.aspx

  1. SPF+DKIM+DMARC don't guarantee Inbox. They get you to the "first-pass" tier. Content quality (subject + body + links) decides the final placement. The first-email body has been pre-tested for spam triggers — keep it verbatim.
  2. You need a working email setup BEFORE this runbook. If you don't have Google Workspace / Outlook / Mailgun already sending as @nicholastempleman.co.uk, this entire page is moot. Set that up first. (Nick: you already have this via Gmail if you use nicholas.templeman@gmail.com — but the from-address should be the @nicholastempleman.co.uk domain for consistency.)
  3. DMARC reports are scary for the first 2 weeks. You'll get daily emails saying "spoof attempt from your domain." That's NORMAL. It means the protocol is working. Don't action them — it's Gmail / Outlook / other large senders backscatter that you cannot stop.
  4. This page assumes nicholastempleman.co.uk is yours and active. If you also own meok.ai / csoai.org / defoneos.co.uk, repeat the SAME process for each. Adding SPF/DKIM/DMARC takes 30 min per domain — run all three in one session.
  5. BIMI (Brand Indicators for Message Identification) is OPTIONAL. BIMI shows your logo in Gmail / Apple Mail inbox. Requires DMARC p=reject for 30+ days AND a verified trademark. Skip for now. Set it post-pilot when trademark is registered.
  6. Email warm-up matters. If your domain is brand-new (never sent email from nicholastempleman.co.uk before), spend 2 weeks sending 20-50 normal emails per day (replies, newsletters, anything) before the 11 first-MOD emails. New domains + high-volume sends from day 1 = instant Junk.
