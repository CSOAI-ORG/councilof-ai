```
                          ┌─────────────────────┐

│  (people tell  │         │  (Watchdog finds │         │  (systems stream │

└───────┬────────┘         └─────────┬────────┘         └─────────┬────────┘
        │                            │                            │
        ▼                            ▼                            ▼
  - Human reports          - RSS scanning                  - MCP server logs
  - Agent reports          - CVE databases                 - API call patterns

  - Question submissions   - News sources                  - Safety thresholds
                           - Academic papers               - Bias detectors
                           - Social media (responsible)    - Sovereignty checks
```

### Channel 1: INBOUND (people tell us)
Anyone can submit:
- **Concern**: "I found this AI system doing X" (incident, bug, bias, violation)
- **Question**: "Is this AI system compliant with EU AI Act?"
- **Evidence**: Hash + cryptographic proof of a claim
- **Endorsement**: "I verify this charter/certification is real"
- **Challenge**: "I disagree with this certification"

### Channel 2: OUTBOUND (Watchdog finds signals)
The Watchdog itself continuously scans:
- **EU AI Office** regulatory updates
- **ICO / FCA / CMA / Ofcom** enforcement actions
- **NVD / CVE** database (CVE-2025-NNNNN)
- **MITRE ATLAS** adversarial ML incidents
- **OWASP** LLM/agent vulnerabilities
- **arXiv** papers on AI safety/alignment/bias
- **RSS feeds** from 200+ sources (HN, Reuters AI, MIT Tech Review, ACM, IEEE)
- **GitHub Advisory Database**
- **Academic preprints** (PsyArXiv, SocArXiv, MedRxiv)
- **Court records** (US, EU, UK) for AI-related litigation

### Channel 3: PASSIVE (systems stream continuously)
Partner systems stream telemetry:
- **MCP servers** report anomalies, errors, compliance violations
- **AI systems** report drift, bias changes, safety incidents
- **Compliance monitors** report regulatory violations
- **SOC tools** report security events
- **Edge devices** report safety-relevant signals

### 6.1 Automatic Escalation

| Severity | Auto-Action |
|---|---|
| **S1 INFO** | Log only |
| **S2 LOW** | Log + monitor trending |
| **S3 MEDIUM** | Log + publish to dashboard + monitor |
| **S4 HIGH** | Log + publish + BFT council notification + 24h SLA investigation |
| **S5 CRITICAL** | Log + publish + **BFT council convenes** + 1h SLA investigation + regulatory escalation |

### 6.2 BFT Council Verification

For S4/S5 signals, the BFT council must vote (quorum 23/33):
- **Confirm**: Signal is real, escalate
- **Dispute**: Signal is false, suppress
- **Investigate**: Need more evidence, delay 7d

### 6.3 Public Disclosure Threshold

| Score (sum of source weights) | Public? | When? |
|---|---|---|

| 1.5-3.0 | Dashboard only | Within 7d |
