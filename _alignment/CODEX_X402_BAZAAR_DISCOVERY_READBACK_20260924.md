The [x402 Foundation Bazaar seller documentation](https://github.com/x402-foundation/x402/blob/main/docs/extensions/bazaar.mdx) says sellers declare the extension in route configuration and that a facilitator's catalogue handling is its own implementation detail. The [CDP discovery search](https://docs.cdp.coinbase.com/api-reference/v2/rest-api/x402-facilitator/search-resources) and [merchant](https://docs.cdp.coinbase.com/api-reference/v2/rest-api/x402-facilitator/get-merchant-resources-by-payto-address) APIs are the readback surfaces. A conformant 402 alone is therefore not proof that CDP indexed the route; a qualifying CDP-facilitated payment and catalogue outcome would need independent verification. There is no documented anonymous submit-URL route for the CDP Bazaar in these primary sources.

Source inspection found no bounded code defect whose repair alone would make CDP list CSOAI: the live v2 challenge already carries the documented Bazaar declaration, while CDP catalogue entry is downstream of facilitator behavior and settlement. The existing `scripts/interop/x402-bazaar-audit.py --json` rightly exited `UNCHECKABLE` without rewriting its report when PayAI's mutable total moved 6,834→6,836. We did not alter the paid rail or manufacture a transaction to force indexing. The next proof is an independently paid qualifying CDP-facilitated request (or explicit catalogue operator outcome) followed by the same anonymous discovery readback; neither occurred in this lane.
