THE SIGIL CHAIN DATA FLOW

From Learner to Verifier

Step 1: Learner completes Course N. Local SIGIL event emitted: "course N completed".
Step 2: Event hashed (SHA-256) and signed with learner's sovereign Ed25519 key.

Step 4: Certificate PDF generated. Contains the Ed25519 signatures + the SIGIL chain hash.
Step 5: Certificate added to Apple Wallet / Google Pay / browser.
Step 6: Verifier (employer / regulator / merchant) scans the QR code → /verify/ → re-computes the signature → confirms the certificate is genuine.
