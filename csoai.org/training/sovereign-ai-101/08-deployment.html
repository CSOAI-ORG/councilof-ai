🚀 Module 8: Deployment

MODULE 8 OF 10 · ⏱ 25 minutes

⚡ 1-Command Install

The CSOAI sovereign stack is designed for 1-command installation. Whether you prefer Docker, Python pip, or npm, you can have a fully sovereign AI deployment running in under 60 seconds.

Choose your path — all three produce an identical sovereign stack with the same SOV3 model, the same Care Floor, the same BFT council, and the same SIGIL chain.

🐳 Docker

# Pull and run the sovereign stack in one command
docker run -d --name sov3-sovereign \
  -p 3101:3101 -p 3200:3200 \
  -v ~/.sov3:/data \
  -e SOV_REGION=EAST \
  -e SOV_CARE_FLOOR=0.95 \
  csoai/sov3:latest

# Verify it's running
curl http://localhost:3101/health
# → {"status":"sovereign","care_floor":0.95,"bft":"12-around-1","sigils":42}

Docker is the recommended path for production deployments. The image is signed (cosign), runs as non-root, supports GPU passthrough, and ships with the 9 open-weights models pre-loaded.

🐍 Python pip

# Install the SOV3 Python package
pip install sov3-sovereign

# Initialise and start the local sovereign stack
sov3 init --region EAST --care-floor 0.95
sov3 start

# You now have a sovereign AI running on localhost:3101
# with the full SIGIL chain + Care Floor + BFT council.

The Python path is ideal for data scientists, ML engineers, and notebook users. It includes the Python SDK, Jupyter integration, and the full sovereign stack as a Python package.

📦 npm

# Install the SOV3 JavaScript SDK + sovereign runtime
npm install -g @csoai/sov3

# Start the local sovereign stack
npx sov3 init --region EAST
npx sov3 start

# Use the JS SDK in your code
const { Sov3 } = require('@csoai/sov3');
const sov = new Sov3({ region: 'EAST' });
const answer = await sov.ask('What is sovereign AI?');
// → answer.text + answer.sigil (Ed25519 + PQC signed)

The npm path is for web developers, Node.js backends, and full-stack applications. It includes the JS SDK, React hooks, Next.js middleware, and the sovereign runtime as an npm package.

🤖 The 9 Open-Weights Models

The sovereign stack ships with 9 open-weights models. All are MIT or Apache-2.0 licensed, all run locally, all preserve the sovereign properties (Care Floor + BFT + SIGIL).

sov3-base

7B · MIT · general-purpose

The default model. Best balance of capability, speed, and resource use. Recommended for most deployments.

sov3-pro

13B · MIT · reasoning

Stronger reasoning, slower inference. Best for compliance audit, legal analysis, complex multi-step tasks.

sov3-edge

1.5B · MIT · edge

Quantised for edge devices (Jetson Orin, Raspberry Pi 5, M2 MacBook). Care Floor still enforced.

sov3-coder

7B · Apache-2.0 · code

Specialised for code generation, review, and refactoring. Trained on sovereign-licensed corpora only.

sov3-legal

13B · MIT · legal

Trained on EU AI Act, GDPR, UK GDPR, ISO 42001, NIST AI RMF. The Article 50 reference model.

sov3-medical

13B · MIT · clinical

Trained on PubMed Central + NICE guidelines + MHRA. Care Floor biased to safety dimension.

sov3-embed

0.3B · MIT · embedding

Vector embeddings. Sovereign RAG. Compatible with pgvector, Qdrant, Milvus.

sov3-vision

7B · MIT · multimodal

Image understanding + Article 50 visual watermarking. C2PA-compatible output.

sov3-tts

0.5B · MIT · speech

Text-to-speech for voice sovereignty. On-device. Care Floor enforced on output text.

📚 The 4 SDKs

Four official SDKs cover the major platforms. All SDKs are open-source (MIT) and emit SIGILs by default.

🐍 Python SDK

pip install sov3-sovereign

Async + sync APIs. Type hints throughout. Pydantic models. AsyncIO-friendly.

from sov3 import Sov3

📜 JavaScript SDK

npm install @csoai/sov3

Browser + Node.js + Deno. TypeScript types. React hooks. Next.js middleware.

import { Sov3 } from '@csoai/sov3'

🍎 Swift SDK

Swift Package Manager

iOS / iPadOS / macOS / visionOS. Native async/await. Care Floor on-device.

import Sov3

🦋 Flutter SDK

flutter pub add sov3

Android + iOS + Web + Windows + macOS + Linux. One codebase, six platforms.

import 'package:sov3/sov3.dart';

🎯 5 Key Takeaways

1. 1-command install via Docker, pip, or npm

All three paths produce the same sovereign stack. Choose your preferred package manager.

2. 9 open-weights models, all MIT/Apache-2.0

General, pro, edge, coder, legal, medical, embed, vision, TTS — all sovereign, all local.

3. 4 SDKs cover Python, JavaScript, Swift, Flutter

Web, server, mobile, desktop, edge — sovereign everywhere, SIGIL everywhere.

4. Configuration via env vars, YAML, or CLI

SOV_REGION, SOV_CARE_FLOOR, SOV_BFT_QUORUM — load-bearing defaults, but every value is configurable.

5. Sovereignty is operational, not aspirational

The Care Floor, BFT council, and SIGIL chain run by default. Sovereignty is what you get out of the box.

📝 Module 8 Quiz

3 Questions

1. Which Docker command starts the sovereign stack?

✓ Answer: B. The simplest 1-command path: docker run -d --name sov3-sovereign -p 3101:3101 csoai/sov3:latest. The full version includes the SOV_REGION env var and persistent volume mount.

2. How many open-weights models ship with the sovereign stack?

✓ Answer: C. 9. base, pro, edge, coder, legal, medical, embed, vision, tts — covering general, reasoning, edge, code, legal, medical, RAG, multimodal, and TTS.

3. Which of these is NOT one of the 4 official SDKs?

✓ Answer: C. Ruby. The 4 official SDKs are Python, JavaScript, Swift, and Flutter. (A Ruby SDK is on the 12-month roadmap but not yet shipped.)
