Preamble

The CSOAI Security Charter establishes the layered, post-quantum, sovereign-by-default security architecture for every action in the sovereign substrate. The Charter draws on the NIST Cybersecurity Framework 2.0 (26 February 2024), ISO/IEC 27001:2022, the EU NIS2 Directive (2022/2555), the UK's Cyber Security and Resilience Bill 2026, the IETF SIGIL chain specification (CSOAI Internal 2024), the NIST PQC standards (FIPS 203 ML-KEM, FIPS 204 ML-DSA, FIPS 205 SLH-DSA, August 2024), and the sovereign substrate principles of CSOAI Ltd.

The Five Functions of NIST CSF 2.0

  • GOVERN (GV): organisational risk governance, supply chain risk management, roles and responsibilities, policies and procedures. Substrate implements as SIGIL chain governance + 33-agent BFT.
  • IDENTIFY (ID): asset inventory, software inventory, hardware inventory, risk assessment, vulnerability management. Substrate implements as 309 SOV3 tools + 531 MCPs + 33 hives.
  • PROTECT (PR): identity management, access control, awareness training, data security, platform security, technology resilience. Substrate implements as Ed25519 + PQC ML-DSA-65 + sovereign AI gate.
  • DETECT (DE): monitoring, anomaly detection, security continuous monitoring, malicious activity detection. Substrate implements as SIGIL chain + Council BFT.
  • RESPOND (RS) + RECOVER (RC): response planning, incident management, recovery planning, improvement. Substrate implements as 33-council incident response + sovereign substrate refresh.

Post-Quantum Cryptography Standards (FIPS 203/204/205, August 2024)

  • FIPS 203 (ML-KEM): Module-Lattice-Based Key-Encapsulation Mechanism, formerly CRYSTALS-Kyber. Three parameter sets: ML-KEM-512, ML-KEM-768, ML-KEM-1024. Substrate default: ML-KEM-768.
  • FIPS 204 (ML-DSA): Module-Lattice-Based Digital Signature Algorithm, formerly CRYSTALS-Dilithium. Three parameter sets: ML-DSA-44, ML-DSA-65, ML-DSA-87. Substrate default: ML-DSA-65.
  • FIPS 205 (SLH-DSA): Stateless Hash-Based Digital Signature Algorithm, formerly SPHINCS+. Used as backup signature scheme. Substrate uses SLH-DSA-SHA2-128s for backup signatures.

Zero Trust Architecture (NIST SP 800-207, August 2020)

The sovereign substrate implements Zero Trust through five pillars:

  1. Identity: Ed25519 sovereign identity per citizen, per agent, per hive.
  2. Device: every substrate component has a hardware-attested identity (Apple Secure Enclave + Apple Neural Engine for sovereign compute).
  3. Network: sovereign substrate runs over wire + post-quantum TLS 1.3 + ML-KEM-768 key exchange.
  4. Application: every sovereign gesture runs in a sandboxed substrate enclave.
  5. Data: SIGIL chain logs every data access with full provenance.

Specific Cases

SolarWinds supply chain attack (December 2020): Russian state actor (APT29 / Cozy Bear) compromised SolarWinds Orion build system; injected SUNBURST malware into 18,000+ customers including US Treasury, US Department of Homeland Security, Microsoft, Intel. Result: NIST CSF 2.0 now includes "GV.SC" (Supply Chain Risk Management) as a category.

Colonial Pipeline ransomware (May 2021): DarkSide ransomware encrypted Colonial Pipeline systems; East Coast fuel supply disrupted for 6 days; $4.4M ransom paid. Result: TSA Pipeline Security Directive 2 issued.

Log4Shell (December 2021): Apache Log4j remote code execution (CVE-2021-44228); CVSS 10.0; affected millions of servers including Cloudflare, Tesla, Twitter, Apple iCloud. Result: substrate requires logging libraries to be SIGIL-signed.

Microsoft Exchange Server compromise (January 2021): HAFNIUM (Chinese state actor) exploited 4 zero-days in Exchange; 30,000+ US organisations affected. Result: substrate requires all backend services to be substrate-enclave isolated.
