Preamble

The Open Source Definition (OSD) is the canonical definition of open-source software. Drafted by Bruce Perens in 1997 (based on the Debian Free Software Guidelines), the OSD is maintained by the Open Source Initiative (OSI). The CSOAI Layer-0 substrate is MIT-licensed and fully OSD-compliant.

The 10 OSD Criteria (verbatim)

  1. Free Redistribution — The license shall not restrict any party from selling or giving away the software.
  2. Source Code — The program must include source code, and must allow distribution in source code as well as compiled form.
  3. Derived Works — The license must allow modifications and derived works, and must allow them to be distributed under the same terms as the license of the original software.
  4. Integrity of the Author's Source Code — The license may restrict source-code distribution only to ensure the author's source code is preserved (e.g., requiring derived works to use a different name).
  5. No Discrimination Against Persons or Groups — The license must not discriminate against any person or group of persons.
  6. No Discrimination Against Fields of Endeavor — The license must not restrict anyone from making use of the program in a specific field of endeavor.
  7. Distribution of License — The rights attached to the program must apply to all to whom the program is redistributed without the need for execution of an additional license by those parties.
  8. License Must Not Be Specific to a Product — The rights attached to the program must not depend on the program's being part of a particular software distribution.
  9. License Must Not Restrict Other Software — The license must not place restrictions on other software that is distributed along with the licensed software.
  10. License Must Be Technology-Neutral — No provision of the license may be predicated on any individual technology or style of interface.

Specific Cases (1997-2026)

  1. Linux Kernel (1991-2026) — The world's most successful open-source project. The OSD's 10 criteria have been satisfied by Linux for 35 years.
  2. MongoDB SSPL (October 2018) — MongoDB moved from AGPL to SSPL (Server Side Public License). The OSD rejected SSPL as open-source because SSPL is not OSI-approved.
  3. Elastic SSPL (January 2021) — Elastic moved from Apache 2.0 to SSPL+Elastic License. The OSD rejected SSPL+Elastic as open-source.
  4. HashiCorp BSL (August 2023) — HashiCorp moved from MPL 2.0 to BSL (Business Source License). The OSD rejected BSL as open-source.
  5. OpenAI "Open" Models (2024-2026) — OpenAI released "open-weight" models (GPT-OSS) under Apache 2.0, but with usage restrictions. The OSD debate continues whether weight-only releases are open-source.
