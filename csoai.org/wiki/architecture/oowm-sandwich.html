OOWM Sandwich

The One-Ouroboros-World-Model: Mamba + MoE + MOM + SOV3 + SIGIL.

Definition

The OOWM Sandwich is CSOAI's central model architecture: a five-layer integration of Mamba-2 long-context memory, MoE-64 reasoning, MOM perceptual routing, SOV3 sovereign binding, and SIGIL cryptographic wrapping. It is the substrate of every sovereign AI product.

Why a Sandwich?

A sandwich is the right metaphor because: (1) each layer is independent and can be swapped, (2) layers can be inspected and audited separately, (3) the architecture scales horizontally (more experts, more modalities) without restructuring, and (4) the layers cooperate through well-defined interfaces (the SIGIL events flowing up and the Mamba state flowing down).

Forward Pass

Input → Mamba (compress) → MoE-64 (reason) → MOM (perceive) → SOV3 (gate) → SIGIL (sign) → Output

At inference, an input query is first compressed by Mamba into a 16-dim state. The state plus query are routed to MoE-64 (4 experts fire). The MoE output is enriched by MOM with perceptual metadata (e.g., "this is a legal query", "user is in UK jurisdiction"). SOV3 checks the action against council rules. SIGIL signs and emits the result.

Backward Pass / Training

Training uses the OOWM Anchor mechanism: each layer's gradient flows through the sandwich, with council-approved sample selection. The Sov3ren Gym (sov_gym_mode_status) runs the continuous training loop.

Sovereign Alignment

The Sandwich is sovereign because every layer enforces a property: Mamba ensures constant memory (data stays local), MoE-64 ensures interpretability (you can see which expert fired), MOM ensures modality awareness, SOV3 ensures rules are enforced, and SIGIL ensures every output is auditable.
