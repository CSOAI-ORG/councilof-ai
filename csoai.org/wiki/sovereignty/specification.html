Sovereign Specification

Technical specification of the five axioms as testable assertions.

sovereign.wiki CSOAI Ltd UK 16939677 4 Jul 2026

Definition

The Sovereign Specification formalises the five axioms (see Axiomatic) as testable assertions. Each axiom yields 2–4 specifications. The full spec is approximately 40 assertions and is the source of truth for the SOV3 sovereignty test suite.

P1 Specifications

  • SPEC-P1-01: Principal can export complete dataset in portable format within 30 days of request
  • SPEC-P1-02: Right-to-be-f honoured within 30 days, with cryptographic proof of deletion
  • SPEC-P1-03: Every byte is hash-chained to SIGIL ledger (see SIGIL Chain)
  • SPEC-P1-04: Access logs readable by principal in real time via sov_sigil_explorer

P2 Specifications

  • SPEC-P2-01: Every actor has a W3C DID resolved by sov_did_resolve
  • SPEC-P2-02: All Ed25519 keys generated on principal's device, never exported (see Ed25519)
  • SPEC-P2-03: No shared credentials — each actor has a unique keypair
  • SPEC-P2-04: PQC upgrade path: keys rotatable to ML-DSA-65 / ML-KEM-768

P3 Specifications

  • SPEC-P3-01: Every access attempt classified as SOVEREIGN / FOREIGN_APPROVED / FOREIGN_BLOCKED within 100ms
  • SPEC-P3-02: Treaty database refreshed daily from UK ICO + EU Commission + US Commerce feeds
  • SPEC-P3-03: Foreign-blocked attempts emit SIGIL F|B event
  • SPEC-P3-04: Eight sovereign realms recognised (UK, USA, EU, CA, AU, NZ, JP, AUKUS)

P4 Specifications

  • SPEC-P4-01: Sovereignty-changing actions require ≥2/3 council majority (see 2-of-3 Majority)
  • SPEC-P4-02: No single admin can revoke keys, change jurisdiction, or alter audit logs
  • SPEC-P4-03: Council members are public DIDs, votes are SIGIL-emitted
  • SPEC-P4-04: BFT tolerates up to 4 malicious nodes out of 13

P5 Specifications

  • SPEC-P5-01: SIGIL chain publicly verifiable via REST API at /v1/sigil/*
  • SPEC-P5-02: OOWM model weights are open-source
  • SPEC-P5-03: Audit log exportable in CSV / JSON / Parquet via sov_dorado_training_export
  • SPEC-P5-04: 90-day default retention with principal-configurable extension

Test Harness

The full specification is enforced by the SOV3 test suite sov_oowm_test, which runs 384+ assertions on each sovereign deployment. Customers can run their own test suite against the public CSOAI infrastructure.

Relation to External Standards

Each spec maps to an external control: SPEC-P1-01 maps to GDPR Art. 20 (right to portability); SPEC-P1-02 maps to GDPR Art. 17 (right to erasure); SPEC-P2-02 maps to NIST SP 800-63B; SPEC-P3-01 maps to EU AI Act Art. 4; SPEC-P4-01 maps to ISO 42001 clause 6; SPEC-P5-01 maps to NIST AI RMF GOVERN function.
